# popga 상태 인코더 (Genie-lite) — 2026-07-24

동시조회(co-visitation) 기반 스토어 잠재공간. "함께 본 스토어 = 같은 소비자 풀".

| 파일 | 내용 |
|---|---|
| embeddings.npz | 전기간(2024-08~2026-07) 학습, 8,388 스토어 × 64d — **전향/운영용** |
| emb_cut0331.npz | 2026-03-31 컷오프 학습, 5,624 스토어 — **백테스트용(시간 누출 방지)** |
| stores.csv | 스토어 메타 (id, 총 유저, 대표 타이틀, 활동 기간) |
| store_weekly.csv.gz | 스토어×주간 조회 유저 시계열 (수요 곡선 원료) |

## 제조법
1. GA4 view_store에서 (유저, 스토어) 유니크 쌍 → 유저(2~100개 조회)별 스토어 쌍 동시출현 카운트 (cooc≥3)
2. PPMI 행렬 → TruncatedSVD 64차원 → L2 정규화
3. 검증: 미피의 이웃 = 하나코·나메코·꿈돌이·원피스 (IP 취향 클러스터, 지역·시기 초월)

## 타깃 좌표 (인과적 — 시간 마스크 준수)
새 팝업의 좌표 = "오픈 前 30일 조회자들이 그 이전에 본 스토어들"의 가중평균 임베딩.
→ 잠재 이웃 top-k의 오픈 前 수요 실측 + 클러스터 관심 추세가 상태 피처.
주의: 조회→방문 전환율은 미학습 — 이웃 간 상대 비교로만 사용 (절대값 직역 금지).

## 재학습
scratchpad/encoder/ 의 추출 SQL·학습 스크립트 참조 (BQ 읽기 전용). 분기 1회 재학습 권장.

## popga 신호 타당성 검정 (2026-07-27) — **음성 확정**

GA4 원본에서 4개 채널을 스토어×주간으로 추출해 방문객 라벨과 대조:

| 채널 | n | 방문객과 상관 r |
|---|---|---|
| view_store (기존 인코더의 유일한 입력) | 199 | 0.056 |
| view_pass_store | 188 | 0.014 |
| click_expand_spot_detail_images | 129 | −0.002 |
| kakao_queue (대기/카카오 유입) | 24 | 0.230 |
| kakao_queue (2026+ 구간만) | 13 | 0.169 |

**결론: popga 행동 데이터는 팝업 방문객 규모의 프록시가 아니다.**
오픈 '후' 조회조차 r=0.034로, 사전 예측력 문제가 아니라 두 숫자가 다른 것을 재고 있다.
대기→방문 배율이 10배~208배로 20배 넘게 흩어지는 것이 직접 증거(같은 대기 273명이
방문 5.7만, 대기 627명이 방문 6천).

원인: 모집단 스케일 불일치 — 스토어당 popga 조회 중앙값 86명 vs 실제 방문 수천~수만.
popga는 팝업 '정보 탐색' 채널이고 실제 방문 유입은 SNS·브랜드팬덤·현장 유동이 지배한다.

**함의**: 상태층 4연속 실패(B/B'/B''/표현학습)의 원인은 방법이 아니라 **신호 부재**였다.
popga를 상태 소스로 쓰는 트랙은 여기서 종료한다. 단 이력 4주+ 스토어(n=34)에서
r=0.427이 나오므로, 관측이 두터운 소수 구간에 한정한 보조 피처로는 재검토 여지가 있다.

## 네이버 검색 트렌드 검정 (2026-07-27) — 상관은 있으나 IP 간 일반화 실패

popga 음성 확정 후 '더 큰 관측 창'으로 시도. 앵커('날씨') 정규화로 요청 간 비교 가능화.

| 검정 | 결과 |
|---|---|
| 검색 level ↔ 방문객 (총계) | r = +0.238 (n=79) |
| 검색 level ↔ 방문객 (일평균) | **r = +0.295** (n=77) — popga의 5배 |
| 다운스트림(IP-그룹 ∩ 시간순 폴드) | 상수 0.376 vs 검색+기간 0.374 — **개선 없음** |

**원인 규명 — IP별 전환율 이질성**:
- IP별 '검색 → 일평균 방문' 오프셋의 IP 간 표준편차 0.89 log10 = **8배 흩어짐**
- 같은 IP 내 반복 관측의 표준편차는 0.30 → **IP를 알면 불확실성이 67% 감소**
- 그런데 반복 관측 IP는 67개 중 10개(15%)뿐

즉 검색량은 정보가 있지만 "짱구 검색 100"과 "폴햄 검색 100"이 서로 다른 방문으로 이어지고,
그 IP별 전환율을 학습하려면 IP당 반복 관측이 필요한데 85%가 1회 관측이다.

**결론: 지금 필요한 것은 더 정교한 모델이 아니라 IP당 반복 관측이다.**
이는 설계서 SFS-1의 Z1(계층 베이즈 부분풀링)이 겨냥한 구조와 정확히 일치하며,
반복 관측을 쌓는 유일한 경로는 전향 사이클(주간 봉인·채점)의 시간 축적이다.

## T1/T1b 태거 검정 (2026-07-28) — 노출량을 알아도 포획률이 병목

**T1(원문 태깅)**: 기획서·계약서 95건에서 예측용 속성 추출. host_daily_traffic 확보율 **9%**
— 몰 자점 입객수는 기획 문서에 기재되지 않음이 확인됨. 즉 LLM이 쓰는 "롯데백화점 부산본점
일평균 4~5만"은 원문이 아니라 **LLM 세계지식**.

**T1b(세계지식 태깅)**: 장소 72곳에 대해 팝업 정보를 주지 않고 장소만 질의(역산 차단).
host_traffic_est = venue_daily_footfall × popup_zone_pass_rate. 확보율 **91%**,
단변량 상관 r=+0.327(팝업 도메인 최고).

**그런데 다운스트림 기여는 둘 다 없음**(내부 n=73, IP-그룹 ∩ 시간순):
| 레인 | 일평균 MAE | vs 상수 |
|---|---|---|
| 상수 중앙값 | 0.378 | — |
| 기존 피처 | 0.329 | ✅ 유의 |
| +T1 | 0.321 | 기여 −0.008 ❌ |
| +T1b | 0.332 | 기여 +0.003 ❌ |

**원인 — 포획률 이질성**:
- 함의 포획률(실측 일평균 / 추정 노출)이 **6배 흩어짐**(log10 sd 0.77)
- 같은 장소 반복 관측에서는 2.9배로 축소 → **장소를 알면 불확실성 41% 감소**
- 그러나 반복 관측 장소는 60곳 중 10곳(17%)뿐

**결론**: 노출량(분모)을 아무리 정확히 알아도 포획률(비율)을 모르면 예측이 안 된다.
그리고 포획률은 개입과 IP에 달렸으며, 그것을 학습하려면 같은 장소·같은 IP의 반복 관측이
필요하다. 이는 네이버 검정(IP별 전환율 8배 흩어짐, IP 내 67% 감소)과 **동일한 구조의 병목**이다.
