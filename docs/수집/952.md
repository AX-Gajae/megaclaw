## 3. 🔴 데몬 — `popupsnap` 의 겹은 **하나가 아니라 넷**이었다

상시 데몬(1분 주기 · launchd)이 **매 회차** `popupsnap` 을 죽이고 있었다.
🔴 **데몬이 첫 회차에 이걸 잡아냈다** — 하루 한 번 크론이었으면 다음 날까지 아무도 몰랐다.

사전등록 **P12** 는 *「원인이 PATH 하나이고 절대경로를 주면 종료 0」* 이라 예측했다. 🔴 **빗맞혔다.**

| 겹 | 무엇 | 고침 |
|---|---|---|
| ① | `FileNotFoundError: 'bq'` — launchd PATH 에 gcloud SDK 가 없다 | `_bq_path()` 로 **경로**를 부른다 |
| ② | `TypeError: unsupported operand type(s) for \|` — gcloud 가 python **3.9.6** 을 잡는다(`bytes \| str` 는 3.10 문법) | `CLOUDSDK_PYTHON` 명시 |
| ③ | `'gcloud' not found but is required for authentication` — `bq` 는 인증을 `gcloud` 로 한다 | SDK bin 을 PATH 에 |
| ④ | 자격증명 환경변수 | 데몬이 `_env()` 로 채운다 |

🔴 **②는 새 병이 아니다.** 티처 #53 C4 가 **옛 크론**에 대해 똑같이 적었다 —
*「`~/.local/bin` 이 PATH 에 없어 gcloud 가 python3.9 를 잡고 `bq` 가 TypeError」*.
**크론에서 고친 것을 launchd 에서 다시 앓았다.** 고친 자리가 아니라 **고치는 방식**이 문제였다.

실측: `env -i HOME=… PATH=/usr/bin:/bin` 에서 이제 **48행을 읽는다**(종료 정상).

🔴 **데몬을 저장소 안으로 들였다** — `runners/harvest_daemon.py` + `runners/com.sweetspot.wm.harvest.plist`.
밖에 둔 이유가 *「사이클 에이전트가 `git add -A` 를 쓴다」* 였는데, 🔴 **그 이유가 참이면**
**고칠 것은 `git add -A` 쪽이지 코드의 거처가 아니다.** 밖에 있는 동안 이 파일은 버전 관리도 ⑤′ 도 안 받았다.
