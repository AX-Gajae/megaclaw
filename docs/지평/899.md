## 5. 🔴 `g(x,t)` 와 맞물리나

### 5.1 지금 `g(x,t)` 가 무엇인지 (읽고 확인함)

`state/fieldmodel.py:104` → `from ingest.visitors import series` → `ingest/visitors.py:213`
`series(div)` 가 `{signguCode: {YYYYMMDD: 방문자수}}` 를 낸다. `div="2"` = **외지인**이 기본이다.
`fieldmodel.field()` 는 학습구간 덮음 90% 로 동네를 고른다.

**직접 돌려서 확인한 분모**: `field(stats_end="20241231")` 이 고르는 동네 = **정확히 261개**,
그중 `11*` = **정확히 25개**. (캐시 전체 코드는 299, 78개 월 파일, 2,349일.)

### 5.2 붙는 키 — **공간연산이 아니라 문자열 다섯 글자다**

```
서울 생활인구 250m :  행정동코드 = "11110515     "   (13자 · 공백 패딩)
                       .strip()[:5]  →  "11110"
방문자 g(x,t)      :  signguCode   =  "11110"
```

**집합이 정확히 같다.** 생활인구 202607 에 나타난 `행정동코드[:5]` 는 **25종**이고,
방문자 자료의 서울 25개 시군구 코드와 **원소까지 일치**한다:

```
11110 11140 11170 11200 11215 11230 11260 11290 11305 11320 11350 11380 11410
11440 11470 11500 11530 11545 11560 11590 11620 11650 11680 11710 11740
```

🔴 **격자 → 시군구 집계는 가능하다. 그것도 면적 가중 재배분이 필요 없다.**
행 하나하나가 이미 `행정동코드` 를 달고 있으므로 **`행정동코드[:5]` 로 `groupby` 하면 끝이고, 그 합은 근사가 아니라 정확하다.**
(§4 의 「5.17% 가 시군구를 가로지른다」는 *격자* 총합을 낼 때의 문제이지 *시군구* 총합에는 안 걸린다 —
가로지르는 칸은 이미 시군구별로 쪼개져 들어온다.)

⚠ **함정 둘**: (가) 13자 패딩을 안 자르면 조인이 0건 난다. (나) 시간 24칸을 합칠지 평균낼지 정해야 한다

**확인된 것**
- 두 원천은 **다른 물건을 잰다**. 생활인구는 *그 시각 거기 있는 내국인 전부*, 방문자는 *KT 기반 방문 사건*이다.
  그래서 상관이 1 이 아닌 것은 결함이 아니라 **새 정보가 있다는 뜻**이다.
- **낮 시간만 잘라내면 외지인과의 수준 상관이 +0.38 → +0.69 로 오른다.** 시간축을 쓰면
  방문자 신호에 더 가까운 양을 만들 수 있다 — 일 단위 `g` 로는 못 하는 일이다.

🔴 **확인 못 한 것 하나**: 현지인 열에서 **구내 pooled r 이 +0.78 인데 구별 r 의 중앙값은 −0.29** 다.
수치는 두 번 확인했지만 **원인은 규명 못 했다**(분산 큰 구 몇이 pooled 를 끌었을 수 있고, 요일 주기의
부호가 도심/주거지에서 반대일 수도 있다). **이 표에서 이 줄만은 결론에 쓰지 마라.**

### 5.4 서울 25 대 전국 261 — 🔴 명시한다

**이 자료는 서울만이다.** `g(x,t)` 의 동네 261개 중 **25개(9.58%)** 에만 해상도를 준다.
나머지 **236개(90.4%) 에는 아무것도 안 준다.**
서울 안에서의 이득은 **8,591/25 ≈ 344배**(898 의 「340배」와 맞는다)이고, 시간축은 **24배**다.
**전국 격자 생활인구가 무료로 생긴 것이 아니다.**

## 7. 저장소에 커밋해도 되나 — **안 된다**

  두 달만으로도 871MB, 전 기간(43개월)이면 **약 18GB**다.

가장 값이 큰 것은 격자가 아니라 **시간**이다. 지금 `g(x,t)` 는 261 동네 × **일별**이고, 이 자료는 서울 25구에
