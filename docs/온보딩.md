# 온보딩 계약서 — 임의 신규 도메인을 파이프에 꽂는 표준 절차 (v1.0 · 사이클 1006 신설)

> **무엇인가.** 파운데이션 판(루프 v5.3 제5장)은 10 도메인으로 정의돼 있다. 실전 질문이
> 커버리지 밖 도메인(예: 드라마·영화·음원)을 물을 때, 그 도메인을 «11번째 스트림»으로 파이프에
> 꽂는 절차와 관문을 이 문서가 정한다. **전례 = 사이클 1006(드라마 · `docs/탐색/1006.md`).**
> 아키텍처의 전제: LODO 제로샷(판 ③)이 서 있는 한, 새 도메인에 필요한 것은 모형이 아니라
> **관측 스트림**(개체 명단 + 일별 관심 곡선 + 개체 텍스트)이다.

## 1. 원천 요건 (조항 59 · 66)

- **무료·공개 원천만**(유료 API 금지 · `WM_ALLOW_PAID_API` 무접촉). 위키 계열이 1순위 전례
  (`ingest/wikidaily941.py` — UA 연락처 명시 · 요청 간격 ≥1.1초 · robots 존중).
- **명단 선정 규칙은 결정론·인기 비의존으로 사전 고정**하고 출처(분류/차트/공보)를 문서화한다.
  후보가 상한을 넘으면 md5(제목) 정렬 같은 «눈 감은» 컷 — 화제성으로 고르면 유형 관찰이 굽는다.
- **실패 3형 의무**: 「없다」(원천 무자료) · 「못 봤다」(규칙상 조회 안 함 — 수를 센다) ·
  「못 읽었다」(오류 — 사유를 값으로). 빈칸은 「없다」가 아니다.
- 원본은 저장소 밖(`/Users/ax/wm_harvest/foundation/onboard_<도메인>/`)에 sha 명부와 함께.
  저장소엔 요약·경로·sha 만(>10MB 반입 금지).

## 2. 스트림 최소 요건 (1006 실측 기준)

| 항목 | 하한 | 사유 |
|---|---|---|
| 개체 수(삼중쌍 가능) | **≥ 30** | 30 미만이면 클러스터 SE 로 승패 문장을 못 쓴다(v5.1 n_val 하한과 같은 정신) |
| 곡선 길이 | **≥ 181일**(S 90 + O 91) | `pretrain/triples.py` 규격 — 91≤span<181 은 「짧은 곡선」으로 따로 신고 |
| 결측일 규약 | [첫 관측일, H] 안 결측 = 0 채움 · 채움 수 게재 | H = 수집 전체의 실제 원천 지평 — 개체별 끝날로 지평을 속이지 않는다 |
| 텍스트 | 개체당 ≥1 문단(출처 URL·수집 시각 명기) | 제로샷의 전이 통로가 텍스트다 — 텍스트 없는 개체는 개체명으로 대체하되 수를 센다 |
| 임베딩 | **현행 배포와 같은 임베더**(지금 Qwen2.5-0.5B · 96토큰 · 평균 풀링) | 다른 임베더 혼합은 제로샷 실측을 오염시킨다(1005 판정 전 4B 금지 전례) |

## 3. 제로샷 검증 관문 (누수 원리 차단 · 조항 66)

1. **순서 기계 강제**: B-스타일(텍스트 전용 · 원핫 없음) K≥5 씨앗 앙상블을 **새 도메인 자료
   반입 «전»** 기존 도메인 자료만으로 학습하고 완료 스탬프(DONE_TRAIN — 끝 시각·모형 sha)를
   쓴다. 수집 러너는 스탬프 없으면 시작을 거부한다. 새 곡선은 **오직 평가에만** 쓴다.
2. **씨앗은 새 집합**(기존 학습·통계 씨앗 전부 회피 · 사전등록에 명기).
3. **앵커 A**: 평가 하네스가 현 배포의 리더보드·report 수치를 «실행 간» ≤1.5e-4 로 재현해야
   새 도메인 수치를 적을 자격이 있다.
4. **주대비 하나(조항 79)**: Δ = MdAPE_persistence − MdAPE_B앙상블 (새 도메인 행 전량 ·
   누적 91일 원 눈금) > max(J_ens, 2×SE^개체클러스터). 나머지(last7 · 덮개율 · A-영벡터 ·
   유형 분할)는 전부 관찰. 게이트마다 **부호 서명 + 방향 탐침**(v5.3).
   🔴 **last7 병기 의무(1006 실측 반영)**: 드라마에서 last7(0.3319)이 B(0.4262)·pers(0.4857)
   를 다 이겼다 — 빠른 감쇠 도메인에선 관성의 «정의»가 승패를 가른다. 온보딩 표는 last7 을
   반드시 나란히 게재하고, last7 에 지면 「제로샷 승」 문언을 못 쓴다(무승부 이하로만).
5. **분포 밖 축 자백 의무**: year 외삽 · 텍스트 분포 · 「언제」의 뜻 — 알고 들어가는 축을
   사전등록에 쓰고 실측을 관찰로 게재한다. 실전 온보딩의 본질적 조건이지 오염이 아니다.

## 4. 판정어 (1006 §5 규격)

앵커 깨짐 → 「무효」 · 개체 <30 → 「원천 불충분」 · Δ > 문턱 → 「온보딩 가능(제로샷 승)」 ·
|Δ| ≤ 문턱 → 「온보딩 가능(무승부 — 스트림 가치는 곡선 자산)」 · Δ < −문턱 → 「스트림은 서고
제로샷은 진다」. **어느 경우에도 온보딩 사이클 자체는 판을 안 건드린다.**

## 5. 정식 도메인 승격 기준 — 판 분모 10 → 11 의 규율 (조항 60)

승격은 **별도 사이클**에서만, 아래 전부를 갖춰:

1. **온보딩 사이클이 「온보딩 가능」 판정**(승 또는 무승부)을 커밋해 두었다.
2. **곡선 성숙**: 개체 ≥30 이 «수집 데몬 상시 편입»으로 이어지고(1회성 수확 금지 —
   `망각 장부` 규율 포함), val 로 뗄 개체 분리 표본 n_val ≥ 30 이 확보된다(v5.1 하한 —
   미달이면 판정 집합 제외 도메인으로 시작).
3. **조항 60 분모 변경 신고 규격**: 사전등록에 ㉮ 판 넷 각각의 「전(10도메인) 값」과
   「후(11도메인) 값」을 나란히 게재할 것을 약속 ㉯ `pretrain/scoreboard.py` 의 도메인 명부
   상수에 새 이름을 «같은 커밋»에서 추가(자동 편입 금지 — 명부는 손으로 넓힌다) ㉰ 최약
   도메인(판 ①)이 새 도메인으로 갈리면 「분모 변경으로 갈렸다」를 판 JSON 낙인으로 ㉱ 이전
   10도메인 눈금의 판도 한 사이클 병기(옛 자·새 자 나란히 — 조항 60-나 «좁히지도 넓히지도
   마라»의 명시적 예외 절차) ㉲ triples 재생성 시 sao.npz sha 갱신을 배포 사슬(manifest ·
   리더보드 · LODO) 전부에 전파하고 LODO 는 11접힘으로 재실측(판 ③ 분모도 는다).
4. **승격 후 첫 사이클**은 새 도메인을 표적으로 못 잡는다(자기가 넣은 분모에서 자기가
   따는 것 방지 — 관찰 한 사이클 숙성).

## 6. 창구(실전 질문) 접속 규율

- 온보딩 «전» 커버리지 밖 질문: 정직 거절 + 「온보딩 가능성」 안내(전례: 드라마 질문 → 1006).
- 온보딩 «후»(승격 전): **관심 곡선 + 등각 구간 + 유사 사례 조회**까지만 — 「수익 예측」은
  이 하네스의 출력이 아니다(관심→수익 환산 계수는 도메인 자료가 따로 필요하고, 그 주장은
  별도 사전등록 없이 못 낸다). 답 문언에 「제로샷(정식 도메인 아님) · 분포 밖 축」 낙인 의무.
- 개체 특정 질문(예: 특정 신작)은 위키 문서가 «있어야» 곡선이 선다 — 문서 없는 신작은
  「원천에 아직 없다(없다·조항 59)」로 답한다.
