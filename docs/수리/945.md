## 3. 🔴 「브랜치를 밀면 산다」가 **안 된다** — 처방이 실패했다

티처 #84 는 *「`archive/pre-github` 를 origin 에 밀어라 · 밀면 「clone 하면 사라진다」가
없어진다」* 고 처방했다. **밀었다. GitHub 이 거부했다.**

```
git push origin archive/pre-github:archive/pre-github
remote: error: File data/state/funding_pool.json is 142.97 MB; this exceeds
        GitHub's file size limit of 100.00 MB
remote: warning: File data/state/fandom_states.json is 76.96 MB
 ! [remote rejected] archive/pre-github -> archive/pre-github (pre-receive hook declined)
```

`git merge-base --is-ancestor archive/pre-github origin/main` 은 **밀기 전에도 뒤에도 NO** 다.
**푸시 안 됨은 태만이 아니라 원격의 하드 한도다.** 힘으로 밀거나(`--force` 금지)
큰 파일을 지워 다시 쓰는 것(**아무것도 지우지 마라**)은 이 사이클의 제약이 막았다.

**대신 한 것 — 정보를 파일로 옮겼다.** 브랜치가 못 가면 **지도를 커밋한다**:
- `data/state/obs_time945_cachemap.json` — 캐시 **54,876** 파일 전량의
  **git 최초추가 커밋**(모든 ref 기준) + mtime. 3.5MB. 🔴 이 중 **54,353** 이
  **origin/main 에 없는 커밋**을 가리킨다.
- `data/state/obs_time945_gitmap.json` — D2 레코드 **25,372** 의 출처파일·mtime·
  git 최초추가(고친 값과 944 의 `or` 값을 **둘 다**). 7.0MB.

## 4. 🔴 위협 모델을 다시 쓴다 — 944 는 틀린 것을 무서워했다

**944 가 쓴 것**: *「mtime 은 `git checkout` 한 번에 사라진다 · 이 파일이 그 근거의 유일한
사본이다 · 오늘 안에 떨궈야 한다」*(`out944b_obstime.py:12`·`:475-476`).

**틀린 곳 둘**
1. `git checkout` 은 **로컬 브랜치를 안 지운다.** 07-29·08-01 스냅샷은 checkout 으로 안 없어진다.
2. checkout 이 mtime 을 갈아엎는 것은 **내용이 다른 파일뿐**이다.
   실측: `git diff --name-only HEAD archive/pre-github -- data/state/cache_*` = **523**.
   54,876 중 **0.95%**. 「checkout 한 번에 사라진다」는 나머지 **99.05%** 에 안 맞는다.

**진짜 위협 넷 (실측)**

| # | 무엇 | 수 | 분모 |
|---|---|---|---|
| **T1** 🔴 | 참 최초추가가 **로컬에만 있는 커밋**을 가리킨다 — 그 **38** 커밋은 `archive/pre-github` **한 ref 에서만** 닿는다(`git branch -a --contains` = 1) | **54,353** | 캐시 54,876 |
| **T2** 🔴 | 그 브랜치는 **origin 이 받기를 거부한다**(142.97MB blob) → `clone` 하면 T1 의 근거가 **통째로** 없어진다 | 커밋 **38/41**(최초추가 커밋 중 origin/main 에 있는 것 **3**) | 최초추가 커밋 41 |
| **T3** | 디스크에 있으나 **어떤 ref 에도 없는** 캐시 파일 — mtime 이 유일한 근거이고 **사본이 없다** | **215** | 54,876 |
| **T4** | mtime 을 실제로 갈아엎는 것: **fresh `clone`**(전량) · 내용이 다른 파일의 checkout(**523**) · `rsync -a` 없이 복사 · 백업 복원 | 523 / 54,876 | 54,876 |

**한 줄로**: 위험한 것은 *동작*(`checkout`)이 아니라 **위치**다 — 근거의 99.05% 가
**한 디스크의 한 브랜치**에만 있고 그 브랜치는 원격이 안 받는다. §3 의 두 파일이 그것을 옮긴다.

## 5. `out944b_obstime.py` 를 **안 고친 이유**(방패가 아니라 검사 가능한 이유)

944 의 산출물 넷은 스탬프에 **`runners/out944b_obstime.py` 의 코드 sha256** 을 적었고
티처 #84 가 `shasum -a 256` 으로 **전량 대조해 일치**를 확인했다. 그 파일을 **주석 한 줄이라도**
고치면 그 대조가 깨진다. 그래서 944 러너는 **한 바이트도 안 건드렸다**(`git diff` 로 확인 가능).
고침은 **새 러너 `out945_obstime.py` 의 `pick_old()`** 에 있고, 그 함수가 실제로 호출된다.

⚠ **남은 빚**: 어떤 코드도 아직 `pick_old` 를 **공용 모듈**로 갖고 있지 않다 —
다음에 같은 지도를 만드는 러너가 또 `or` 를 쓸 수 있다. 다음 후보로 올린다.
