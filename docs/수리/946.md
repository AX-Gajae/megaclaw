## 1. 무엇이 틀렸었나

`git config core.quotepath` 가 **unset(기본 true)** 이다. 그래서
`git ls-files` · `git ls-tree --name-only` · `git log --name-only` 는 비-ASCII 경로를
**8진 이스케이프**해서 낸다:

```
"data/state/cache_aladin/AB6IX_B_COMPLETE__\353\257\270\353\213\210_1\354\247\221_.html"
```

그 줄은 `"` 로 시작한다. 그래서 `startswith("data/state/cache_")` 같은 **평범한 필터가
그 줄을 조용히 버린다** — 예외도, 0 도 아니다. **작고 그럴듯한 양수**가 남는다.

그 양수가 **215** 였고, **네 사이클(943 · 944 · 티처 #84 · 945)이 그 위에 수를 쌓았다.**

## 4. 두 번째 경로 — 🔴 **결함을 공유하지 않는지 확인했다**

945 는 두 경로로 셌는데 **둘 다 인용부호를 놓쳤다**(티처 #85 C2). 규칙 A 도 규칙 B 도
git 의 **경로 포매팅 층**을 지난 문자열을 받았기 때문이다. 🔴 **같은 층을 지나면 한 경로다.**

| | 첫 경로 `out946_quotefix.py` | **두 번째 경로 `out946_recount.py`** |
|---|---|---|
| git | `ls-tree --name-only -z -c core.quotePath=false` (층을 **쓰되 끈다**) | 🔴 `git cat-file --batch` 로 **트리 객체 원 바이트** 직접 파싱 — 층이 **없다** |
| 디스크 | `Path.rglob` (str) | 🔴 `os.scandir(bytes)` — str 디코딩 없음 |
| 비교 공간 | `str` | 🔴 `bytes` |
| census 파서 | `ast` | 🔴 `tokenize` |

**결함 공유 시험**(주장이 아니라 실측): `core.quotepath` 를 **켜고 끄고 두 번** 돌렸다.

| | quotepath=true | quotepath=false | 차 |
|---|---|---|---|
| 두 번째 경로(트리 객체) | **54,876** | **54,876** | 🔴 **0 / 0** |
| 🔴 음성 대조 — 날 것 `ls-tree --name-only` | **54,661** | **54,876** | **215** |

즉 **첫 경로는 그 설정을 끄기 때문에 옳고, 두 번째 경로는 그 설정을 아예 안 탄다.**
날 것은 같은 자리에서 **탄다** — 그것이 이 시험의 음성 대조다.

**다섯 수가 두 경로에서 같다**(`out946_recount.json:마 · 첫 경로와 수 대조/🔴 어긋난 항목` = `[]`):
디스크 캐시 **54,876** · `디스크−트리` **0** · `트리−디스크` **0** · 옛지도−디스크 **215** ·
census 자리 **14**(날 것 7 + 의도적 1 = tokenize 의 **8**).

⚠ **census 대조는 「남의 파일 750」으로 제한했다.** 두 경로의 「자리」 정의가 다르므로
(첫 경로 = argv 로 건너가는 것만 · 두 번째 = 경로 토큰을 품은 문자열 뭉치)
**946 자신의 파일에서는 두 수가 원리상 안 맞는다** — 946 은 `PATH_TOKENS` 상수와 사유
문자열을 잔뜩 이고 있다. **뺀 목록은 첫 경로의 산출물에서 읽었다**(손 나열 아님).

🔴 **커밋된 실물과 대조**(945 C3 가 걸린 자리): 두 번째 경로가 자기 입력 다섯의
**작업 트리 sha256 과 `git cat-file blob HEAD:<경로>` 의 sha256 을 둘 다 계산해 견준다.**
945 는 `--ran` 을 **손으로 타이핑**했고 대조 코드가 없어서 검증기가 대상보다 **2분 24초 먼저**
돈 것을 아무도 못 봤다. 🔴 **그래서 이 러너는 산출물을 커밋한 뒤에 다시 돌린다** —
「아직 안 커밋됐다」와 「내용이 다르다」를 갈라 적는다(조항 59).
