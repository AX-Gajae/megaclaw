## 🔴 §0 · 이 사전등록이 「측정 전에 쓰였다」의 증거는 무엇인가 (티처 #71 C6 대응)

915 가 이 자백을 안 해서 티처 #71 C6 에 걸렸다. **먼저 적는다.**

- 이 파일은 **산출물과 같은 커밋에 들어갈 가능성이 높다**(주 세션이 한 번에 커밋한다).
  그러면 「측정보다 먼저 썼다」의 증거는 **파일 mtime 하나뿐**이고, mtime 은
  **덮어쓰면 갱신된다**. 즉 이 증거는 **위조 가능하고 약하다**.
- 그래서 보강을 셋 둔다. 셋 다 완전하지 않다는 것도 같이 적는다:
  1. 이 파일의 **sha256 을 산출물 `runners/out919_geocode.json` 의 도장에 박는다.**
     측정 뒤 이 파일을 고치면 sha 가 어긋나 드러난다. **다만 「그 전에 뭐라고 썼는지」는
     못 복원한다** — 어긋남만 보인다.
  2. 산출물에 **이 파일의 mtime 과 러너 코드의 mtime 과 측정 시작·끝 시각**을 넷 다 박는다.
  3. 🔴 **그래도 「내가 이 파일을 측정 뒤에 통째로 다시 썼다」는 가설은 이 증거들로 배제되지
     않는다.** 배제하려면 사전등록만 **먼저 따로 커밋**해야 하는데, 이 팔은 커밋 권한이 없다
     (주 세션이 커밋한다). **그러므로 이 사전등록의 순서 증거는 「약하다」로 읽어라.**

## §1 · 무엇을 하는 팔인가

노트 915 가 서울 생활인구 250m 격자를 열었다(행 146,611,427 · 격자 8,880 · 날짜 577).
그런데 판 유보 3,775 중 격자에 붙는 것이 **93행 · 서로 다른 격자 37칸**뿐이었다.

915 가 못 붙은 이유를 갈라 셌다(`runners/out915_link.json:③ 부착 — 유보 합집합(분모 185)`):

| 이유 | 건수 |
|---|---|
| 🔴 **좌표 열이 링크로 안 닿음** | **83** |
| 좌표는 있는데 서울 상자 밖 | 6 |
| 서울 안인데 격자 집합에 없음 | 3 |
| (붙음) | 93 |
| 합 = 분모 | **185** |

**즉 자료가 없는 게 아니라 위치 키가 안 뚫린 것이다.**
이 팔의 일은 **주소/장소명 → 좌표** 를 뚫어 부착 행을 늘리는 것이다.

🔴 **이 팔은 판정을 하지 않는다.** 판 ρ 도 소수 라벨 곡선도 안 쓴다.
자는 **회복 행 수와 서로 다른 격자(군집) 수** 둘뿐이다.

## §2 · ⓪ 방향 설계 — v3.3 네 칸

### ⓪-가 · 자 + 🔴 **검출력 줄**

**자를 뗐다.** 판 ρ(문턱 0.00353 · 유보 3,775)는 이번 물음을 **못 잰다** —
이번 물음은 「효과가 있나」가 아니라 「행이 붙나」이고, 붙는 행이 없으면 어떤 자도 못 돈다.
**대신 재는 것**: 부착 행 수(정수 계수) · 서로 다른 격자 수(정수 계수). 둘 다 **전수 계수**다.

> **자 = 부착 계수(전수)** · 표본 n = 판 유보 **3,775** ·
> 군집 K = 서로 다른 격자(현재 **37**) · 잡음 = **0(표집이 아니라 전수 계수)** ·
> 🔴 **가를 수 있는 최소 효과 = 1행 / 1격자**

**재려는 효과의 예상 크기**와 **원리상 상한**을 미리 적는다 — 915 가 이걸 안 해서 걸렸다:

| 모집단 | 유보 행 | 지금 붙음 | 🔴 원리상 상한 |
|---|---|---|---|
| 팝업 유보 | 65 | 23 | 65 |
| 시장팝업 유보 | 126 | 73 | 126 |
| 두 도메인 합집합(겹침 6 제거) | **185** | **93** | **185** |
| 판 유보 전체 | 3,775 | 93 | ? (아래) |

🔴🔴 **그러므로 문턱 「붙는 행 ≥ 200」은 팝업 두 도메인만으로는 원리상 도달 불가다.**
상한이 **185 < 200** 이다. **이 계산은 zip 을 한 줄도 안 읽고, 지오코딩을 한 건도 안 하고
지금 할 수 있다** — 915 가 「BCa 폭 0.64 를 9.13GB 안 읽고 셀 수 있었다」로 걸린 바로 그 자리다.

**그래서 문턱 200 을 넘는 길은 논리적으로 둘뿐이다:**
- **(가)** 팝업 두 도메인 **밖의 도메인**에 위치 키가 실재하고 그것이 뚫린다
  (후보: **영화 유보 406** — 극장은 물리적 장소다. 아래 §3 경로 F)

🔴 **(나) 가 되면 「그래도 프로브는 돌려 봤다」를 하지 않는다.**

## §3 · 회복 경로 — **측정 전에 여섯을 못 박는다**

각 경로에 대해 **① 몇 건을 새로 붙였나 ② 왜 못 붙었나** 를 갈라 센다.

| 경로 | 무엇 | 입력 |
|---|---|---|
| **A** | spot 링크는 닿는데 `latitude/longitude` 가 **빈 칸** → `spot_addr.json` 의 주소로 좌표를 얻는다 | `record_store_link.json` · `platform_spots.csv` · `spot_addr.json` |
| **B** | spot 링크 **자체가 없다** → 레코드의 장소명(`conditions.location.venue_name` / `conditions.venue`)을 `platform_spots.csv` 의 `title` 과 문자열 매칭 | 레코드 · `platform_spots.csv` |
| **C** | 레코드가 **주소 문자열을 직접** 갖는다(`conditions.derived.competition.matched_address`) → 주소 → 좌표 | `data/records/*.json` |
| **D** | 🔴 **저장소 내부 gazetteer** — (도로명주소 → 좌표) 쌍 전량을 `platform_spots.csv` 에서 만들고, 정규화 후 ① 정확일치 ② 도로명+건물번호 일치 ③ 도로명만 일치(그 도로의 좌표 중앙값) 로 3단 매칭 | `platform_spots.csv` |
| **E** | 🔴 **동 단위** — 구/동 이름 → 행정동코드 → 그 동의 격자 집합. **다른 분모다** | `ingest/visitors.py` · 격자 지도 |
| **F** | 🔴 **탐색** — 팝업 밖 도메인(특히 **영화 406**)에 극장/장소 열이 실재하는가 | `data/state/kobis_axes.json` 등 |

**공통 규칙**
- 🔴 **좌표를 얻은 뒤에는 915 와 똑같은 관을 쓴다**: `grid_of()` (EPSG:5179 `다사` 해독) →
  격자 집합 8,880 에 드는가 → 날짜가 지평(2025-01-01~2026-07-31)과 겹치는가.
  **관을 바꾸면 93 과 못 견준다.**
- 🔴 **경로 D 의 ③(도로명만 일치)은 250m 격자보다 거친 매칭일 수 있다.**
  그래서 **③ 으로 붙은 건은 따로 세고, 헤드라인에서 뺀 수와 넣은 수를 둘 다 적는다.**
- 🔴 **경로 E(동 단위)는 헤드라인 부착 수에 절대 더하지 않는다.** 따로 표를 만든다.

## §4 · 배선 검사 — 측정 전에 통과해야 하는 것

1. **sha256** — 입력 파일과 코드 전량의 sha256 을 산출물에 박는다.
2. **그 열이 정말 닿았나** — 각 경로가 읽는 열마다 **비어 있지 않은 값의 개수**를 센다.
   🔴 **0 이면 「그 열이 없다」로 적고 그 경로는 「못 했다」다 — 「좌표가 없다」가 아니다**(조항 59).
3. 🔴 **심은 결함이 실제로 발화하는지** — 아래 넷을 심어서 **잡히는지** 확인한다.
   **잡히지 않으면 그 검사는 「원리상 발화 불가」이고 배선 검사는 실패다**(티처 #71 C3 재발 방지):
   - (ㄱ) 좌표를 서울 밖(대구)으로 바꾼다 → 「서울 상자 밖」 칸이 늘어야 한다
   - (ㄴ) 격자 집합을 비운다 → 부착이 **0** 이 되어야 한다
   - (ㄷ) gazetteer 주소를 전부 망가뜨린다 → 경로 D 회복이 **0** 이 되어야 한다
   - (ㄹ) 🔴 **음성 대조** — 아무것도 안 심은 사본은 원래 값이 나와야 한다
4. **자기시험** — 아무 경로도 켜지 않으면 915 의 값(좌표 102 · 격자 93 · 격자 37)을
   **그대로 재현해야 한다.** 재현 못 하면 관이 다른 것이고 **측정을 안 한다.**
