🔴 **규약의 값은 진짜다**(939·940 에서 거짓 문장을 열 개 넘게 잡았다). **그러나 값이 진짜인 것과

**규칙**
1. 🔴 **탐색 레인의 결과는 그 사이클의 결론에 절대 안 들어간다** — 다음 사이클의 **후보**가 될 뿐이다

3. 🔴 **매 사이클 탐색 레인을 반드시 하나 돌린다.** 「여유 있으면」이 아니다 —
   최근 5사이클의 탐색 팔 실물이 **0** 이었다.
4. **수리 레인은 한 사이클에 하나까지.** 지금은 수리가 본 사이클을 잡아먹는다.
5. 🔴 **어느 레인인지를 커밋 제목 첫 낱말로 적는다** — `[판정]` · `[탐색]` · `[수리]`.

**무엇을 겨냥하나**: 규약 폭풍을 **판정 레인 안으로 격리**해서 다른 갈래로 도망갈 이유를 없앤다.
🔴 그러면 `analysis` 갈래(908~912)는 **탐색 레인의 정당한 산출물**이 되고 **병합이 가능해진다.**

## ⓪ 🔴 방향 설계 — 자율주행 셋 ← v3 신설

**①(cycle_open) 보다 먼저 한다.** 열린 이슈를 보기 전에 봐야 **이슈 목록에 갇히지 않는다.**

구분이 안 된다(조항 59).

### ⓪-가 · 자를 뗄 것인가

> **지금의 자(판 ρ · 문턱 0.00353 · 12도메인 유보 3,775)가 이번 물음을 잴 수 있는가?**

사용자 규약: *"지표가 방법을 가두면 지표를 뗀다."*

- **판이 못 재는 물음**은 판으로 재지 마라. 897 이 실제로 그 벽에 부딪혔다 —
  잡음의 단위가 **씨앗이 아니라 날짜 군집 540** 이라 판 유보에선 대부분의 아키텍처 디테일이
  **원리상 판정 불능**이다(`docs/아키텍처.md` §3 n-power 표).
- 🔴 **자를 뗄 때는 「무엇으로 대신 재는지」를 같이 적는다.** 안 적으면 자를 뗀 게 아니라
  **판정을 포기한 것**이다.
- ⚠ 자를 떼는 것은 **문턱을 낮추는 것이 아니다.** 문턱 0.00353 은 팔 차이에서 나오므로
  판 수준값이 바뀌어도 안 움직인다 — **떼는 대상은 자 전체이지 문턱 하나가 아니다.**

#### 🔴🔴 검출력 줄 ← v3.3 신설 (노트 915 가 이것 없이 원리상 못 가르는 자리까지 갔다)

> **이 표본에서 이 자가 가를 수 있는 최소 효과는 얼마인가? 그 수를 여기 적어라.**

**못 채우면 측정 단계로 안 넘어간다.** 「대충 될 것 같다」는 값이 아니다.

- **적는 형식**: `자 = <이름> · 표본 n = <행> · 군집 K = <군집> · 잡음 = <SD 또는 구간 폭> ·
  🔴 가를 수 있는 최소 효과 = <수>` — 그리고 **재려는 효과의 예상 크기**를 나란히 적는다
- 🔴 **행 수로 걸지 마라.** 915 의 사전등록은 문턱 셋을 전부 개수(행·격자·날짜)로 걸었고
  「붙는 행 ≥38」을 93 이 넘어서 4단계까지 갔다. 그런데 **군집이 37 이라 BCa 폭이
  k=16 에서 0.64, k=8 에서 0.88** 이었다 — 잴 수 있는 최소 효과가 ρ 0.3~0.6 인 자였다.
  **9.13GB 를 한 줄도 안 읽고 할 수 있던 계산이다.**
- 🔴 **잡음 바닥을 같이 적는다.** 판 ρ 의 채택 문턱 0.00353 은 **순수 난수 열 하나의 잡음
  바닥 0.01055 의 1/3** 이다(노트 892) — 「채택」과 「잡음」을 원리상 못 가르는 구간이 있다

## ② 팬아웃 편성 — 🔴 이 단계가 v1 에 없었다

옛 지시서: *"겹쳐 돌리면 같은 파일을 두 에이전트가 만진다"* → 그래서 **한 번에 하나만**
돌렸고 사이클의 대부분이 대기였다.

**정정: 그 문장은 파일이 겹칠 때만 참이다. 겹치지 않으면 겹쳐 돌려야 한다.**

### 표준 편성

| 자리 | 무엇 | 파일 집합 |
|---|---|---|
| **본 사이클** ×1 | 다음 노트 하나를 끝까지 (사전등록→배선검사→측정→판정→논문→PR) | 새로 만드는 `runners/*<번호>*` · `runners/out<번호>_*` · 새 논문 스텝 · 원장 **추가만** |
| **수리** ×N | 티처의 치명/중대 하나씩 | 각자 **다른 서브트리** — `ingest/` · `paper/` · 특정 `runners/` 파일 |
| 🔴 **탐색** ×1 | ⓪-다 의 팔. **판정 없음** | `docs/탐색/<사이클>.md` 하나 · 저장소 코드 **읽기만** |
| **주 세션** | 이슈·카드·커밋 취합·머지 | 카드(저장소 밖) · git |

🔴 **탐색 팔은 파일 하나만 쓴다.** 그래서 다른 팔과 **절대** 안 겹치고, 겹칠 걱정 없이
매 사이클 상시로 띄울 수 있다. 그게 이 자리를 상설로 만드는 이유다 —
**탐색은 여유 있을 때 하는 게 아니라 자리가 정해져 있어서 하는 것이다.**

### 🔴 팬아웃 규칙 — 안 지키면 정말로 충돌한다

1. **각 에이전트에게 허용/금지 파일 목록을 명시적으로 준다.** *"알아서 조심해라"* 는 안 통한다.
2. **`git add -A` 금지.** 남의 미완성 편집을 쓸어 담는다.
3. **`git commit` 은 본 사이클 에이전트 하나만.** 수리 담당들은 **파일만 고치고 끝낸다** —
   커밋은 주 세션이 모아서 한다. 한 워킹트리에서 둘이 커밋하면 서로를 삼킨다.
4. **`git checkout` · `git stash` · `git reset` 은 전원 금지.** 남의 작업을 날린다.
5. 읽기만 하는 산출물도 **"지금 남이 고치고 있다"** 고 알려 주고, **읽은 값을 자기 산출물에
   복사**시킨다(중간에 바뀔 수 있다).
6. 파일이 **정말** 겹치면 `isolation: "worktree"`. 비싸니 정말 겹칠 때만.

### 프롬프트에 반드시 넣을 것

- **"인계 카드부터 읽어라"** — 대화 요약을 길게 넘기지 않는다. 누적 맥락이 오염원이다
