## 모듈

### E0 — 평가 배선 (GroupTimeSplit + 페어드 벤치)
- **입력** 레코드 (ip_key, 개최일, trust, domain)
- **출력** 폴드 인덱스, 페어드 부트스트랩 CI, 모델-프리 하한 3종
- **기법** IP-GroupKFold ∩ rolling-origin 교차, 반복 5회, 페어드 부트스트랩. 폴드 내부 fit 강제(FeatureScaler·PCA·TE·shrinkage k). 폴드마다 SharedEncoder 재초기화. 채점 라벨은 A·B만.
- **근거** 실측으로 현재 비교가 무효다. state/encoder.py:72의 mu/sd가 분할 전 전체 X에서 계산되고(transductive 누출), :79의 _split이 IP·시간 무시 랜덤이며, train(encoder=..., freeze=False)는 같은 enc 객체가 5폴드 내내 학습돼 테스트 폴드를 본다. 결정적으로 NN 0.53은 상수 중앙값 0.5152보다 나쁘다 — 아키텍처 실패가 아니라 미학습 증상이다. 그리고 LLM 0.07은 rolling-v3-A의 visitors n=9(min-train 354의 최후 9건)이고 NN 0.53은 랜덤 5-fold n=372다. 두 숫자는 같은 표에 올릴 수 없다.

### T1 — 텍스트 인코더: 동결 char-SVD16 + LLM 오프라인 속성 태거
- **입력** intervention.concept / experience_elements / promotions / staging_tags / location.*, 그리고 Drive 기획서 원문
- **출력** 16차원 동결 임베딩 + 40~60개 순서형·이산 속성 컬럼 (그중 5~8개는 원문에서 추출한 숫자)
- **기법** (a) 기존 char_wb 2~4gram TF-IDF→SVD를 24→16으로 축소·동결. (b) FeatLLM/CAAFE 계열 오프라인 태거 — 고정 온톨로지로 체험밀도·굿즈유무·예약제·포토존수·콜라보강도·IP인지폭을 순서형으로, 그리고 ★원문 숫자★(운영 예상 방문/일, 숙주 행사·몰 일평균 입객, 회차 캐파, 증정물 준비 수량)를 수치로 추출. 추론 시 LLM 미호출. harness/predictor_agent.py의 2패스 프로토콜 재사용 → API 비용 0.
- **근거** 임베딩 업그레이드는 실측으로 죽었다. paraphrase-multilingual-MiniLM-L12-v2(로컬 캐시됨)로 372건을 임베딩해 폴드 내부 PCA/PLS로 투입한 결과: PCA8 0.4109 / PCA16 0.4129 / PCA32 0.4266 / PLS4 0.4625 / PLS8 0.5351 / raw384 0.6091 — 전부 현행 char-SVD24(0.4042)보다 나쁘다. 텍스트 단독은 0.4920(상수 0.5152 대비 겨우 0.023). 반면 LLM 커밋 로그를 열어보면 이기는 이유가 임베딩이 아니다: 'RTPU2606 베리즈 더현대B2 7일 5,902명(843/일, entry)을 하한 기준' 같은 단위정규화 선례 검색과 '롯데백화점 부산본점 일평균 입객 4~5만명 × 포획률 2~4%' 같은 원문·세계지식 숫자다. 24건 중 13건의 assumptions가 기획서 운영 예상치 계열 키워드를 인용한다. 즉 처방은 '더 좋은 벡터'가 아니라 '원문의 숫자를 컬럼으로'다.

### N1 — 수치 인코더: 물리 스케일 오프셋 분해
- **입력** days, store_count, area_pyeong, total_capacity, weekend_share, host_traffic 추정치(T1 산출)
- **출력** 고정 오프셋 3종(log10 days, log10 store_count, log10 exposure_base) + 잔여 강도 타깃 η
- **기법** log10 ŷ = log10(days) + log10(store_count) + log10(exposure_base) + b_unit + η(x). 앞 두 항은 계수 1로 고정(학습 안 함), exposure_base는 숙주트래픽 또는 캐파 상한을 계층 축소로 채움. 학습은 η에 대해서만. piecewise-linear/periodic 수치 임베딩은 n<1000에서 새 과적합 표면이라 Stage 2로 유예.
- **근거** 실측 분해가 명령한다. IP-GroupKFold 릿지에서 days 단독 0.4384, days+store_count 0.4389, days+store+venue_tier+is_host 0.4357, 전체 48피처 0.4086, 상수 0.5152. 총계 개선 0.107 중 0.077(72%)이 기간 산수다. 일평균 축으로 바꾸면 상수 0.4222 vs 모델 0.4003 — 순수 수요 신호는 0.022(5%)뿐. 산수를 오프셋으로 빼지 않으면 모델이 '오래 열면 많이 온다'를 재학습하며 성능표를 부풀리고, 그 아래 진짜 신호는 영영 안 보인다. 이것이 preprocess.py P2(기간 교락)의 정본 구현이다.

### C1 — 범주 인코더: 계층 3층 부분풀링 (매장→체인/몰→티어)
- **입력** venue_name / host_traffic_note / 기획사 / 카테고리
- **출력** 축소추정 스칼라 1~3개 + 부모 폴백 값
- **기법** b_venue = λ·mean_venue + (1−λ)·b_parent, λ = n/(n+k), 3층 중첩(개별 매장 → 몰·체인 → 티어). k는 폴드 내부 CV로. 자유 nn.Embedding 금지. entity_graph.py의 FAMILY 딕셔너리(현재 5개)를 LLM 1회 배치로 수백 개 규모(브랜드→모기업, 매장→체인, 그룹→기획사)로 확장하는 것이 선결 작업.
- **근거** 실측이 순진한 타깃 인코딩을 기각한다. shrink-TE(k=5)를 붙이면 총계 축에서 0.4086 → 0.4615(venue), 0.4812(venue+ip)로 **악화**한다. 원인이 데이터에 있다: venue 고유값 271개인데 재등장하는 행이 127개뿐이고, IP 노드 948개 중 반복 관측 IP는 33개(78행)다. 부모 폴백 없는 축소는 대부분의 행에 전역 평균 + 잡음을 꽂는 것과 같다. 반대로 host_traffic_note 254건은 '이마트 울산점', '파르나스몰 B1 센트럴라운지'처럼 **매장 정체성**이라, 이걸 3계층으로 묶으면 T1이 뽑는 숙주 트래픽 숫자의 사전분포가 된다. 현행 VENUE_TIER는 13개 키워드 딕셔너리로 271개 매장을 3단계로 뭉갠 것이다.

### S1 — 시간 인코더: Hawkes 지수감쇠 커널 뱅크 + 고정 캘린더 푸리에
- **입력** 개최일, 해당 IP의 과거 관측 {(t_j, label_j, domain_j)}
- **출력** 8 스칼라 (s_τ, n_τ for τ∈{3,12,36개월}) + 6 캘린더 스칼라 + first_event 플래그
- **기법** s_τ(t)=Σ_j log10(y_j)·exp(−Δt_j/τ), n_τ(t)=Σ_j exp(−Δt_j/τ), τ∈{3,12,36}. 캘린더는 sin/cos(2π·doy/365), sin/cos(2π·doy/182.5), sin/cos(2π·dow/7) — 주파수 고정. 학습 파라미터 0. dataset_v2.py의 ip_state_block()에서 months_since_log 단일 스칼라를 이걸로 교체.
- **근거** 현 상태 블록이 물리적으로 비어 있다 — popup_table.npz의 IP 상태 7피처가 372행 중 310행(83%)에서 전부 0이고, 그 결과 state-only 릿지 MAE가 0.5191로 **상수 중앙값 0.5152보다 나쁘다**. 반대로 상태 블록을 빼면(no-state 40피처) 0.4046으로 오히려 좋아진다. 즉 지금 SharedEncoder에 들어가는 입력은 순수 잡음이다. 그리고 IP당 이력이 0~5건이므로 THP/Latent ODE/mTAND/RoPE는 범주 오류다(mTAND 논문 실측으로도 ODE-RNN은 16.5분/epoch). Bochner 정리가 말하는 이동불변 커널을 근사할 이유가 없는 구간이라 정확히 계산한다. Time2Vec 학습형 ω,φ는 금지 — 자유 주파수는 372행에서 임의 고주파에 라벨을 맞춘다.

### U1 — 관측모형: 단위 오프셋 + 검열(Tobit) 우도
- **입력** counting_method / counting_basis, label_trust 등급, 라벨 원문(하한 표현 여부)
- **출력** b_unit 오프셋 5종(entry≡0 고정), σ_grade 5종, 검열 여부 플래그
- **기법** log10 y_obs = f(x) + b_unit + ε, ε~N(0, σ²_grade). 단위 오프셋은 학습, 추론 시 b_entry로 고정 출력. '초동 8천 장' 같은 하한 표현은 −log P(y>c) Tobit 우도로, 아이돌 로그 구간 라벨(<3천/3천~1만/…)은 같은 우도의 양측 검열로 — 두 도메인 라벨 온톨로지가 한 우도로 통일된다. σ_grade는 손으로 찍지 말고 기저모형 잔차에서 추정(BIV), 가중은 w=1/σ²_grade.
- **근거** 실측: unit one-hot 단독 릿지가 0.4841, trust one-hot 단독이 0.4997, is_market 단독이 0.4947 (상수 0.5152). 모델이 '몇 명이 왔나'가 아니라 '누가 센 숫자인가'를 학습하고 있다는 직접 증거다. 이걸 피처로 두면 수요 신호를 흉내내며 성능표를 부풀리지만, 추론 시엔 예측 대상의 counting_method를 모르므로 실전에서 붕괴한다. 오프셋으로 분리해야 f(x)가 깨끗해진다. 또 아이돌 실데이터를 열어보면 라벨 63건 중 42건이 C등급이고 그 다수가 '초동 8천 장…' 하한 마스킹이다 — 이걸 점라벨로 회귀하면 체계적 하향 편향이 생기고, 이 편향은 TRUST_W 가중으로는 원리적으로 못 고친다.

### Z1 — 공유 잠재 상태 θ: 계층 베이즈 부분풀링 (신경망 아님)
- **입력** N1이 오프셋을 뺀 잔여 강도 η, IP 키, 부모 IP(C1의 계열), 도메인
- **출력** θ_IP 사후분포(평균·분산), τ²(계층 분산), λ_d(도메인별 발현 계수)
- **기법** η_{d,i} = λ_d·θ_{IP(i)} + f_d(x_i) + ε_i, θ_IP ~ N(θ_parent, τ²), θ_parent ~ N(0,σ²), ε_i ~ N(0,σ²_grade). NumPyro/PyMC로 CPU 수십 초, 또는 statsmodels MixedLM 선형판으로 시작해 f_d는 GBDT 잔차로 2단 적합. θ 차원은 1로 시작, τ²가 유의하면 2~3으로.
- **근거** 이것이 사용자 가설('팬덤 상태는 글로 표현되지 않는 잠재변수, 도메인별로 다르게 발현')의 유일하게 식별 가능한 형태다. θ는 결정론적 인코더 출력이 아니라 **사전분포를 가진 잠재변수**이고, '글로 표현 안 됨'은 '모든 관측 피처를 뺀 뒤 남는 IP 고유 잔차'로 조작적 정의된다 — τ²의 사후분포가 곧 '정말 잠재가 있는가'의 검정이 된다. 실측 근거가 낙관적이다: 반복 관측 IP 33개의 within-IP sd가 0.314인데 전체 sd는 0.717 → ICC ≈ 0.81. 동시에 실측 제약이 가혹하다: θ 식별 예산은 within-IP 대조 45개뿐이고, 팝업↔아이돌 **양쪽에 라벨이 있는 IP는 5개**(킥플립·뉴진스·QWER·베이비몬스터·르세라핌)다. 그래서 λ_d(크로스 도메인 발현)는 지금 식별 불가 — Stage 1 게이트로 잠근다. nn.Embedding(948, d)는 d=1이어도 파라미터가 라벨 행수(372)를 넘으므로 자유 임베딩은 원천적으로 성립하지 않는다.

### D1 — 도메인 디코더: FiLM 조건화 + 도메인별 분위수 헤드
- **입력** θ (공유), 도메인 ID, 도메인 고유 개입 피처
- **출력** 도메인별 3분위수 {q10, q50, q90}
- **기법** h_d = γ_d ⊙ θ + β_d (도메인당 2×dim 파라미터). 헤드 출력 1→3, 가중 pinball loss. 팝업은 연속, 아이돌은 U1의 구간 검열 우도. 분위수 교차는 출력 정렬로 후처리. 도메인 원-핫 concat은 절편만 바꾸지만 FiLM은 스케일까지 바꾼다.
- **근거** 제약 '도메인이 앞으로 더 늘어남'을 정면으로 흡수한다 — 도메인 추가 비용이 헤드 전체 복제(수백 파라미터)가 아니라 γ,β 두 벡터(θ가 1차원이면 4~6 파라미터)다. 표본 요구가 거의 안 늘어난다. 분위수 헤드는 80% 구간의 원재료를 만들고, 라벨 신뢰등급을 'E급은 덜 믿는다'(가중치)가 아니라 'E급은 더 불확실하다'(구간 폭)로 옮겨준다 — 후자가 통계적으로 옳은 표현이다. TFT 절제에서 게이팅 제거 시 **가장 작은** 데이터셋(Volatility)의 P90 손실이 +4.1%로 타격이 가장 컸다 — 작을수록 조건부 변조가 중요하다는 직접 증거.

### P1 — LLM 융합: 잔차 스태킹 (오염 감사 통과 조건부)
- **입력** LLM stage1 출력(visitors_total point/low/high), 층1~4 예측, 신뢰등급, 단위
- **출력** 최종 점추정 = ŷ_LLM + g(·), 그리고 '언제 LLM을 믿을지'의 학습된 게이트
- **기법** ŷ_final = ŷ_LLM + g(층1~4 출력, 등급, 단위, 결측패턴). g는 depth 3 GBDT 또는 릿지 — 잔차만 학습하므로 타깃 분산이 작아 소표본에서 학습 가능. 백테스트 전 구간의 LLM 예측은 predictor_agent.py 2패스로 미리 채워 API 비용 0. 각 폴드 컷오프 이전 정보만으로 생성해야 하며 그 자체가 누출 검증 대상.
- **근거** LLM을 이기려는 것은 소표본에서 비현실적이고, 상보적일 근거가 실측으로 있다. LLM은 세계지식(롯데백화점 부산본점 일평균 입객)·원문 독해·단위정규화 선례 검색에 강하고, 표형 모델은 계약구조·면적·이력 통계에 강하다. 다만 **선행 조건이 절대적이다**: 0.07은 n=9 표본이고, 프롬프트 규칙 7이 '기획서의 운영 예상치를 point의 기준선으로 사용하라'고 명시적으로 지시한다. 이건 누출이라기보다 정보 비대칭이지만, 어느 쪽이든 0.07을 목표선으로 삼으면 설계가 오염된다. 감사 3종(컷오프 이후만 재채점 / 엔티티명 마스킹 재채점 / 오차와 언론 노출량의 상관)을 통과하지 못하면 P1은 폐기한다 — 통과 못 한 채 스태킹하면 누출을 파이프라인에 영구 고착시킨다.

### Q1 — 캘리브레이터: Mondrian CV+ / CQR (도메인 × 신뢰 2×2)
- **입력** D1의 분위수 출력 또는 임의 점추정기의 out-of-fold 잔차
- **출력** 80% 예측구간 + 셀별 실측 커버리지 + 반폭
- **기법** CV+ (split 금지 — n_cal 낭비). conformity score E = max(q̂_lo − y, y − q̂_hi)를 out-of-fold로 모아 Mondrian 그룹(도메인 × {A·B, C~E})별 분위수. SSBC 베타 보정으로 '평균 80%'가 아니라 '확률 90%로 최소 80%'. 시간 드리프트 구간은 Barber et al.의 가중 분위수판.
- **근거** 실측이 pooled 캘리브레이션을 기각한다. GBDT+CV+ 로 재보니 marginal 커버리지 0.804로 합격처럼 보이지만 조건부는 A·B 0.853 / C~E 0.749 — 저신뢰 라벨에서 10pp 붕괴가 marginal 뒤에 숨는다. 등급별 Mondrian으로 분리하면 0.807 / 0.806으로 복구되고 반폭이 0.579 / 0.748로 갈린다(정직해진다). 폭의 기준선도 실측으로 확보했다: 모델-프리 marginal 반폭 0.831 log10(46배 밴드) vs GBDT+CV+ 0.642(19.3배). 이 아래로 못 내려가면 '구간을 만들었다'가 아니라 '모델이 아무것도 모른다'로 읽어야 한다. split conformal은 372행에서 n_cal 74~130을 떼야 하고 그때 커버리지 sd가 4.5pp라 방법 간 비교 해상도가 사라진다.

### B1~B4 — 챌린저 레인 (같은 폴드 병주, 별도 장부)
- **입력** 층1~2가 만든 동일 피처 테이블
- **출력** 레인별 log10 MAE + 구간 + 페어드 부트스트랩 CI
- **기법** B1 GBDT(HistGradientBoosting/LightGBM) + quantile objective 3종 — sklearn 1.6에 이미 있음. B2 TabPFN v2 회귀 predict(output_type='quantiles') — n≲1000이 설계 스윗스팟. B3 LLM 예측기를 **같은 폴드 전수**에 agent 경로로 재실행. B4 모델-프리 하한 3종(상수 중앙값 0.5152 / days-only 0.4384 / marginal conformal 반폭 0.831).
- **근거** 우리 NN이 상수 중앙값보다 나쁜 상태(0.53 > 0.5152)에서 프론티어 구조를 논하는 것은 순서가 틀렸다. Grinsztajn et al.(45셋·2만 GPU시간)은 ~1만 표본 구간에서 트리가 여전히 SOTA라고 보고했고, 우리 피처 구성(무정보 피처 다수·마스크 11개·축 정렬 임계효과)이 정확히 트리에 유리하다. ⚠ 실측 제약: 로컬이 Python 3.9.6이라 **TabPFN 설치 불가**(3.10+ 요구) — 별도 venv가 선행 작업이다. torch 2.8·sklearn 1.6·sentence-transformers 5.1.2는 확인됨, lightgbm/catboost/mapie/crepes/statsmodels는 미설치.

## 학습 계획
【원칙】 n<1000에서 하이퍼파라미터 탐색은 검증셋 과적합만 낳는다. 튜닝하는 대신 사전지식을 구조로 못 박는다.

■ 손실 함수 (층별)
  1. 층2 물리 오프셋: 학습하지 않음. log10(days)·log10(store_count) 계수는 1로 고정.
     — 학습형으로 두면 모델이 즉시 여기에 용량을 태운다(실측: days 단독이 전체 개선의 72%).
  2. 층3 잔여 강도 η: 가중 pinball {0.1, 0.5, 0.9} + 검열(Tobit) 우도.
     L = Σ_i w_i · Σ_q ρ_q(η_i − η̂_i^q),  단 하한 라벨은 ρ 대신 −log P(y > c) 로 교체.
     아이돌 로그 구간 라벨은 −log[Φ((c_hi−μ)/σ) − Φ((c_lo−μ)/σ)] — 같은 코드로 처리.
  3. 가중 w_i: TRUST_W={A:1.0,B:0.8,C:0.5,D:0.25,E:0.25}를 손으로 찍는 것을 폐기하고
     w_i = 1/σ̂²_grade(i) 로 교체. σ̂_grade는 기저모형(릿지) 잔차의 등급별 표준편차에서 추정(BIV).
     배치 내 정규화로 '거의 무잡음 등급'이 유효 학습률을 폭주시키는 것을 막는다.
     ※ D등급은 18건뿐이라 σ 추정이 불안정 → C와 병합해 4등급으로 추정.
  4. 층3 계층 사전: θ_IP ~ N(θ_parent, τ²) — τ²는 학습(사후분포로), 손으로 고정하지 않는다.

■ 정규화 (파라미터 예산이 아니라 사전분포로)
  · 앙상블: 시드 10개 deep ensemble. 파라미터가 수백 개라 CPU에서 사실상 공짜이고,
    소표본 NN의 시드 분산이 일반화 오차의 큰 부분이다. 반드시 먼저 할 것.
  · modality dropout p=0.3 — 텍스트 브랜치 전체를 확률적으로 0 마스킹 + indicator 비트.
    텍스트가 헤드 입력의 62%를 차지해 가장 빨리 암기되는 경로를 끊는다.
  · 엔티티 ID 드롭아웃 p=0.3 — θ_IP를 부모값 또는 전역평균으로 치환.
    운영 시점 입력의 상당 비율이 미지 IP(948개 중 반복 33개)이므로 이 강건성이 필수.
  · GMU 게이트: z = σ(W_z[x_txt ‖ x_tab]), h = z⊙h_txt + (1−z)⊙h_tab.
    학습된 게이트 평균값이 '텍스트가 실제로 쓰이는가'의 계기판 — 현재 실측상 z는 0에 가까울 것으로
    예상되며, 그게 맞다면 텍스트 브랜치를 잘라내는 결정 근거가 된다.
  · Feat-Mix 증강(ExcelFormer): 두 샘플의 피처 부분집합 교환 + 라벨을 교환 비율로 보간. 30줄.
    n=372·저신호 피처 다수 조건에서 소표본 효과가 검증된 몇 안 되는 기법. Stage 1에서 도입.
  · 자유 nn.Embedding 금지. 하드 제약: 임베딩 파라미터 총수 C×d ≪ n_eff.

■ 최적화
  · AdamW lr=2e-3, weight_decay=3e-4 (TabM 기본값 이식), 400 full-batch 스텝 대신
    **학습 폴드 내부 검증 분할로 early stopping** — 현행 400회 고정 스텝에 조기종료·검증셋이
    없는 것이 R²=0.01의 유력한 원인(과적합이 아니라 미학습).
  · 계층 베이즈 부분은 NumPyro NUTS 또는 statsmodels MixedLM(선형 근사)로 CPU 수십 초.
  · f_d(x)는 GBDT 2단 적합(랜덤효과 흡수 후 잔차) — Sigrist(2023)가 고카디널리티에서
    '랜덤효과+부스팅' > '랜덤효과+DNN'을 보고했고 우리 조건이 그 조건이다.

■ 폴드 위생 (하나라도 어기면 장부가 깨진다)
  · 모든 fit(scaler, PCA/SVD, 타깃 인코딩 축소계수 k, σ_grade, τ 그리드)은 학습 폴드 내부에서만.
  · 폴드마다 인코더 재초기화 — 현행 train(encoder=enc, freeze=False)는 같은 객체가 5폴드를 관통한다.
  · LLM 피처(T1 태거 산출, P1 점추정)는 각 폴드 컷오프 이전 정보만으로 생성.
    태거 프롬프트에 outcome 필드·개최 후 기사 차단 목록을 걸고, 산출물을 프롬프트 버전 해시로 봉인.
  · HPO를 하는 순간 소모 폴드 장부에 기록. n=372에서 폴드 하나는 74건이고, CAAFE류 자동 피처
    탐색은 검증셋을 태우는 다중검정 기계다.

■ 착수 순서 (계산 예산 로컬 CPU 기준, 각 단계 반나절 이내)
  1일차: E0 배선 교체 + B4 하한 3종 고정 → 기존 0.53/0.07을 장부에서 '무효'로 표시
  2일차: N1 물리 분해 + U1 단위 오프셋 → 일평균 축 기준선 재측정
  3일차: S1 커널 뱅크 + C1 계층 축소 → 상태 블록 부활 여부 판정
  4일차: D1 분위수 헤드 + Q1 Mondrian CV+ → 80% 구간 첫 실측
  5일차: B1 GBDT / B3 LLM 전수 재실행 페어드 비교
  (병행) Python 3.10+ venv 구축 → B2 TabPFN 레인 개통
  (병행) T1 LLM 태거 온톨로지 설계 — 이게 기대이득이 가장 크므로 사람 하루를 여기 쓴다

## 평가 계획
【대전제】 지금 존재하는 두 숫자(NN 0.53, LLM 0.07)는 둘 다 벤치마크로 쓸 수 없다. 첫 작업은 모델 개선이 아니라 눈금 교체다.

■ 폴드 프로토콜
  · 주 프로토콜: IP-GroupKFold(5) ∩ rolling-origin(시간순). IP가 train/test에 갈리지 않고
    미래→과거 정보가 새지 않는 유일한 구성. 반복 5회(그룹 배정 시드 변경) + 페어드 부트스트랩.
  · 콜드스타트 홀드아웃: '학습에 없던 IP만' 별도 채점 셀. 랜덤 분할은 IP 누출을 허용한다.
  · 채점 라벨은 A·B(197건)만. C~E(175건)로 채점하면 개선 신호가 라벨 잡음에 묻힌다.
    (실측: 등급별 y 평균이 A·B 3.83 vs C~E 4.18 — dispersive 잡음이 아니라 선택 편향/정의 불일치다)

■ 두 타깃 축을 항상 함께 보고 (이걸 안 하면 산수를 실력으로 착각한다)

  │ 구조화 48 GBDT       │ 0.4255   │ —        │

■ 구간 평가
  · 보고 필수 3종: 실측 커버리지 / 평균 반폭(log10) / interval score. 폭 없는 커버리지는 무의미하다.
  · 하한 병기: 모델-프리 marginal 반폭 0.831 log10(46.0배 밴드). GBDT+CV+ 는 0.642(19.3배).
    신규 모델의 반폭이 0.642 아래로 안 내려가면 구간이 아니라 무지의 고백이다.
  · Mondrian 셀별(도메인 × {A·B, C~E}) 커버리지를 이항 신뢰구간과 함께.
    실측 경고: pooled는 marginal 0.804지만 조건부 A·B 0.853 / C~E 0.749다.
  · 커버리지 해상도 표를 명시하고 그 안의 차이는 우열로 읽지 않는다:
    n_cal=75 → sd 4.5pp / 150 → 3.2pp / 300 → 2.3pp / 1000 → 1.3pp.
    현 n=372에서 ±3~5pp 이내 차이는 방법 간 우열이 아니다.

■ LLM 공정 비교 (요구사항 5)
  · 필수: predictor_agent.py 2패스 경로($0)로 **같은 IP-그룹·시간 폴드 전수**에 LLM 재실행.

    rev_mm의 MAPE 0.6%·Spearman 1.00은 계약 산수 되풀이라 예측력 지표가 아니다.
    참고: rolling-v3-B 동일 폴드 0.0959, rolling-v4-latent 0.0750 — 폴드 간 변동이 이미 크다.
  · 오염·비대칭 감사 3종 (P1 채택의 전제 조건):
    ① 모델 사전학습 컷오프 이후 개최분만으로 재채점
    ② 브랜드·IP·기획사·매장명 마스킹 후 재채점
    ③ LLM 오차와 해당 건의 언론 노출량의 상관 검정(음의 상관이면 회상)
  · 정보 비대칭 분해: 프롬프트 규칙 7이 '기획서의 운영 예상치를 point 기준선으로 쓰라'고 명시하고,
    24개 커밋 중 13개의 assumptions가 그 계열을 인용한다. 따라서 추가 절제 1종:
    ④ 기획서 원문 접근을 끊고 우리 48컬럼 테이블과 동일한 정보만 준 LLM 재실행.
    ④의 성적이 표형 모델 수준으로 떨어지면 격차의 정체는 '아키텍처 열위'가 아니라 '입력 결핍'이고,
    처방은 T1 태거(원문 숫자의 컬럼화)이지 인코더 재설계가 아니다.

■ 전이 이득 판정 (요구사항 3)
  · 페어드 절제 ≥10회 반복 + 페어드 부트스트랩 CI. transfer_eval()의 현행 ±0.01 판정 임계는
    폴드 표준편차(실측 0.004~0.015)와 구분 불가하므로 폐기.
  · 검정력 하한을 사전 선언: |Δ| < 0.03 log10 은 '이득 없음'과 구분 불가 → '측정 불가'로 보고.
  · 대조군 필수 3종: 도메인별 단독 / 풀링(도메인 더미만) / Daumé 증강 피처.
    풀링이 단독을 못 이기면 도메인 전이 이득이 데이터에 없다는 뜻이고, 그 상태에서 MoE·PCGrad·
    어댑터·CARTE를 논하는 것은 전부 무의미하다.
  · 잠재변수 검정: τ²(계층 분산)의 사후 신뢰구간이 0을 제외하는가 = '팬덤 상태가 실재하는가'.
    λ_d(도메인별 발현) 사후가 0에서 떨어지는가 = '같은 상태가 두 행동으로 발현하는가'.
    실측 식별 예산: within-IP 대조 45개(팝업), 크로스 도메인 라벨 IP 5개.

## 리스크 (실측 감사 — 최우선 열람)
- 【최우선】 LLM 0.07 vs NN 0.53 비교는 실측으로 무효다. 0.07은 cycle_log/rolling-v3-A의 visitors n=9(min-train 354 이후 최후 9건, rolling-origin)이고, 0.53은 랜덤 5-fold n=372에 전체 데이터 표준화 누출까지 낀 값이다. 같은 폴드에 올리기 전에는 '7.5배 열세'라는 전제 자체가 성립하지 않으며, 이 숫자를 목표로 삼으면 아키텍처 선택 전체가 잘못된 방향을 향한다. 참고로 동일 폴드의 rolling-v3-B는 0.0959, v4-latent는 0.0750으로 폴드 변동이 이미 크다.
- 【치명】 현행 NN(0.53)은 상수 중앙값 예측기(0.5152)보다 나쁘다. 즉 아무것도 학습하지 못했다. 원인은 아키텍처가 아니라 (a) 400회 고정 full-batch 스텝에 조기종료·검증셋 없음 (b) state/encoder.py:72의 전체 데이터 mu/sd 표준화 누출 (c) :79의 IP·시간 무시 랜덤 분할 (d) train(encoder, freeze=False)이 같은 enc 객체를 5폴드 관통. RSSM/JEPA/TabM으로 바꿔도 같은 배선이면 같은 자리에 머문다.
- 【치명】 공유 인코더의 입력이 비어 있다. popup_table.npz의 IP 상태 7피처가 372행 중 310행(83%)에서 전부 0이고, state-only 릿지 MAE 0.5191은 상수 중앙값 0.5152보다 나쁘며, 상태 블록을 제거하면(no-state 40피처) 0.4046으로 오히려 좋아진다. SharedEncoder는 310행을 전부 같은 상수 z로 보내므로 transfer_eval()은 구조상 전이 이득을 낼 수 없다 — 전이가 '중립'으로 나와도 가설의 반증이 아니라 입력 공백의 반영이다.
- 【치명】 크로스 도메인 전이 가설이 통계적으로 식별 불가능하다. entity_graph를 실행해 세어보면 아이돌 노드 248개 중 팝업에도 등장하는 것이 13개, **양쪽에 라벨이 있는 IP는 5개**(킥플립·뉴진스·QWER·베이비몬스터·르세라핌)다. λ_d(도메인별 발현 계수)를 5개 관측으로 추정할 수 없다. 도메인 공동학습은 Stage 1 게이트로 잠그고, 그전까지는 도메인 내 부분풀링만 한다.
- 【데이터 실태】 아이돌 라벨이 리서치 가정(250~280)의 4분의 1이다. data/idol_records는 250건이지만 chodong 라벨 보유는 **63건**뿐이고 그중 42건이 C등급(하한 마스킹 '초동 8천 장…'), B등급 20건, D 1건이다. debut_date는 242/250. 즉 아이돌 도메인은 '표본 250'이 아니라 '검열된 표본 63'이며, Tobit/구간 우도 없이는 체계적 하향 편향이 들어간다.
- 【실측 부정 결과】 텍스트 임베딩 업그레이드는 이득이 없다. 로컬 캐시된 paraphrase-multilingual-MiniLM-L12-v2로 372건을 임베딩해 폴드 내부 투영으로 붙인 결과 PCA8 0.4109 / PCA16 0.4129 / PCA32 0.4266 / PLS4 0.4625 / PLS8 0.5351 / raw384 0.6091 — 전부 현행 char-TFIDF-SVD24(0.4042)보다 나쁘다. 텍스트 단독은 0.4920으로 상수(0.5152) 대비 겨우 0.023. 지도형 투영(PLS)은 n=372에서 폴드 내부 fit에도 불구하고 심하게 과적합한다. BGE-M3/Qwen3로 바꾼다고 이 판정이 뒤집힐 근거는 없다 — 문제는 인코더가 아니라 임베딩되는 텍스트가 193자짜리 정규화 요약이라는 것이다.
- 【실측 부정 결과】 순진한 타깃 인코딩은 성능을 깎는다. shrink-TE(k=5)를 붙이면 총계 축 0.4086 → venue TE 0.4615 → venue+ip TE 0.4812로 악화한다. venue 고유값 271개 중 재등장 행이 127개뿐이고 IP 노드 948개 중 반복 관측이 33개(78행)라, 부모 폴백 없는 축소는 대부분의 행에 전역평균+잡음을 꽂는다. entity_graph.py의 FAMILY가 5개 항목뿐인 것이 이 실패의 직접 원인이다.
- 【해석 함정】 표형 모델의 '실력'은 대부분 산수와 출처다. 상수 0.5152 → days 단독 0.4384 → 전체 48피처 0.4086. 개선 0.107 중 0.077(72%)이 기간 산수이고, unit one-hot 단독 0.4841 / trust 단독 0.4997 / is_market 단독 0.4947은 모델이 '누가 센 숫자인가'를 학습하고 있다는 증거다. 일평균 축에서는 상수 0.4222 vs 모델 0.4003 — 순수 수요 신호가 0.022(5%)뿐이다. 총계 축 성적만 보고하면 이 사실이 영원히 가려진다.
- 【환경 제약】 로컬이 Python 3.9.6이라 TabPFN 설치 불가(3.10+ 요구). 확인된 가용: torch 2.8.0, sklearn 1.6.1, numpy 2.0.2, scipy 1.13.1, sentence-transformers 5.1.2, HF 캐시에 Qwen3-Embedding-4B·multilingual-MiniLM 존재(8.8GB). 미설치: lightgbm, catboost, mapie, crepes, statsmodels, gpboost. 즉 '가장 강한 소표본 챌린저'를 세우려면 별도 venv 구축이 선행 작업이며, 이걸 안 하면 GBDT(sklearn HistGradientBoosting)가 유일한 트리 레인이다.
- 【검정력】 판정 불가 구간이 넓다. IP-그룹 5fold 반복에서 폴드 간 sd가 릿지 0.004, GBDT 0.005~0.015다. 0.03 log10 미만의 차이는 표본잡음과 구분 불가하므로 그보다 작은 '이득'을 쫓으면 잡음을 아키텍처로 오인한다. 구간 쪽도 마찬가지 — n_cal=75면 커버리지 sd가 4.5pp라 ±5pp 이내 차이는 무정보다. transfer_eval()의 현행 ±0.01 판정 임계는 폴드 sd보다 작아 그대로는 쓸 수 없다.
- 【부정 전이의 가장 그럴듯한 경로】 두 도메인의 선택 메커니즘이 다르다. 팝업은 '집행된 기획'만, 아이돌은 '정식 데뷔한 팀'만 관측되므로 생존 편향의 형태가 다르고, 공유 인코더가 이 차이를 '팬덤 상태'로 오인해 학습할 위험이 있다. 게다가 prior_log_mean은 '반복 실행될 만큼 성공한 IP'만 보므로 낙관 편향된 추정량이다. 도메인 추가 시마다 단독 학습 대비 페어드 이득 검정을 통과해야 하는 게이트가 필수다.
- 【라벨 온톨로지 혼입】 입장/참여/유동/구매를 한 y로 회귀하고 있고 신뢰등급 C~E가 175/372(47%)다. 여기서 오는 분산은 twohot 헤드나 conformal이 '넓은 구간'으로 흡수할 뿐 줄이지는 못한다. 실측: pooled 구간의 조건부 커버리지가 A·B 0.853 / C~E 0.749로 갈리고, 등급별 y 평균도 3.83 vs 4.18로 다르다 — dispersive 잡음이 아니라 정의 불일치다. 이건 모델 문제가 아니라 인제스트 문제이며 아키텍처로 덮으면 안 된다.
- 【conformal 전제 붕괴】 교환가능성이 3중으로 위협받는다. (a) rolling-origin·시간 드리프트(2023→2026 팝업 시장) (b) 신뢰 가중 w를 캘리브 점수에 곱하면 보장이 깨진다(Mondrian 층화로 대체할 것) (c) impute-then-predict는 marginal 커버는 유지해도 결측패턴 조건부로는 무너진다. 우리는 mask 피처 11개가 이미 있으니 결측 개수를 보조 그룹으로 쓸 수 있으나, 층을 3축으로 쪼개면 셀당 표본이 굶는다 — 2×2가 상한이다.
- 【LLM 태거의 누출 재발 위험】 T1 태거와 P1 스태킹은 LLM 경로를 파이프라인 안으로 끌어들인다. 현재 시간 마스크는 자극 빌더에만 걸려 있고(target_stimulus가 outcome을 제외, 2026-07-24 누출 사고 후 basis 원문도 제외), 태거에는 아직 없다. 태거 프롬프트에 결과 필드·개최 후 기사 차단 목록을 확장하지 않으면 라벨이 피처로 돌아 들어온다 — 그리고 그 누출은 잔차 스태킹으로 세탁되어 보이지 않게 된다.

## 단계별 롤아웃

### Stage 0 — 눈금 교체 (지금, 팝업 n=372 / 아이돌 라벨 63). 모델을 바꾸지 않는다.
**할 일** E0 평가 배선 전면 교체(IP-GroupKFold ∩ rolling-origin, 폴드 내부 fit, 폴드마다 인코더 재초기화, 채점 A·B 라벨만) + B4 모델-프리 하한 3종 고정 + 총계/일평균 두 축 동시 보고. 기존 0.53·0.07을 장부에서 '프로토콜 상이 — 무효'로 명시. LLM을 predictor_agent 경로($0)로 같은 폴드 전수 재실행하고 오염·비대칭 감사 4종(컷오프 이후만 / 엔티티 마스킹 / 노출량 상관 / 원문 접근 차단) 수행. 병행: Python 3.10+ venv 구축해 TabPFN·LightGBM 레인 개통.

**통과 게이트** ① 모든 레인이 동일 폴드·동일 라벨필터로 한 표에 오른다. ② LLM의 같은 폴드 전수 성적이 n≥100으로 재측정된다(현재 n=9). ③ 감사 4종의 결과가 기록된다 — 특히 '원문 접근 차단' 절제에서 LLM 성적이 표형 수준(≈0.40)으로 떨어지면 진단을 '입력 결핍'으로 확정하고 Stage 1의 우선순위를 T1 태거로 고정한다. ④ 현행 NN이 상수 중앙값(총계 0.5152 / 일평균 0.4222)을 이기는지 여부가 확정된다. **이 게이트 전에는 어떤 아키텍처 변경도 착수 금지.**

### Stage 1 — 구조 이식 (팝업 n≈372 유지, 아이돌 라벨 63→200 확보 병행)
**할 일** N1 물리 스케일 분해(days·store_count를 계수 1 오프셋으로 고정, 잔여 강도 η만 학습) + U1 관측모형(단위 오프셋 b_unit, entry≡0 고정 / C등급 하한 라벨 Tobit / 아이돌 구간 라벨 양측 검열 / σ_grade를 잔차에서 추정해 w=1/σ²) + S1 Hawkes 커널 뱅크 8스칼라 + 고정 캘린더 푸리에 + C1 계층 3층 축소(entity_graph FAMILY를 LLM 1회 배치로 5개→수백 개 확장) + D1 분위수 헤드 3출력 + Q1 Mondrian CV+ 캘리브레이션. 그리고 최대 기대이득 항목: T1 LLM 오프라인 속성 태거(40~60 순서형 + 원문 숫자 5~8종: 운영 예상 방문/일, 숙주 몰 일평균 입객, 회차 캐파). 도메인 공동학습은 아직 하지 않는다.

**통과 게이트** ① **일평균 축**에서 상수 중앙값 0.4222를 페어드 부트스트랩 95% CI가 0을 제외하며 이긴다(총계 축 개선은 산수라 게이트로 인정하지 않는다). ② 80% 구간의 Mondrian 4셀 조건부 커버리지가 전부 0.72~0.88, 평균 반폭이 GBDT+CV+ 기준선 0.642 log10 아래. ③ S1 커널 뱅크 투입 후 상태 블록의 비영 비율이 17%→50% 이상으로 오르고, state-only 성적이 상수(0.5152)를 넘어선다 — 안 넘으면 공유 인코더에 넣을 신호가 여전히 없다는 뜻이므로 Stage 2 전이 착수를 보류한다. ④ T1 태거 투입의 페어드 이득이 ≥0.03 log10(검정력 하한). ⑤ 아이돌 라벨이 200건 이상 확보되고 크로스 도메인 라벨 IP가 5→20개 이상.

### Stage 2 — 잠재 상태 개통 (총 n≈650~900, 아이돌 라벨 200+, 크로스 IP 20+)
**할 일** Z1 계층 베이즈 부분풀링 개통 — η_{d,i} = λ_d·θ_IP + f_d(x) + ε, θ_IP ~ N(θ_parent, τ²), NumPyro/MixedLM 선형판부터. D1 FiLM 도메인 조건화(γ_d, β_d)로 두 도메인 공동학습. 도메인별 타깃 정규화는 z-정규화 유지(아이돌 n<200이면 QuantileTransformer 승격 보류). deep ensemble ×10, modality dropout p=0.3, 엔티티 ID 드롭아웃 p=0.3, Feat-Mix 증강 도입. P1 LLM 잔차 스태킹은 Stage 0 감사 통과 시에만 개통. 대조군 3종(도메인 단독 / 풀링+도메인더미 / Daumé 증강 피처) 상시 병주.

**통과 게이트** ① τ²의 사후 신뢰구간이 0을 제외한다 = '글로 표현되지 않는 잠재 상태가 실재한다'가 처음으로 실증된다. 제외하지 못하면 공유 인코더 가설을 기각하고 관측 피처 확충으로 회귀한다. ② λ_아이돌 사후가 0에서 떨어진다 = '같은 상태가 두 행동으로 발현한다'. ③ 페어드 절제 ≥10회에서 공동학습이 도메인 단독 대비 ≥0.03 log10 개선(CI 0 제외)이고, 어느 도메인에서도 부정 전이(−0.03 이하)가 없다. ④ Daumé 증강 피처 대조군을 이긴다 — 못 이기면 '전이 이득'의 정체는 단순 스케일 정렬이므로 계층모형을 유지하고 신경망 공유 인코더는 계속 보류. ⑤ 콜드스타트 홀드아웃(학습에 없던 IP)에서 성적 붕괴가 20% 이내.

### Stage 3 — 학습형 확장 (총 n≈1,500~2,000, 도메인 3개)
**할 일** 여기서 처음으로 학습형 인코더가 정당화된다. D1 헤드를 TabM 블록(k=32 파라미터 공유 암묵 앙상블)으로 교체하거나 twohot symexp 이산 회귀 헤드(41버킷, log10 1~7)로 교체 — 후자는 구간이 버킷 CDF에서 공짜로 나온다. S1을 Deep Sets/SeFT 순열불변 풀링 ρ(Σφ(Δt, log10 y, domain))으로 승격(이력 5건 이상 IP가 두터워진 뒤). 수치 피처 piecewise-linear/periodic 임베딩 도입. 3번째 도메인은 어댑터 계약 7종 + FiLM γ,β 두 벡터만으로 붙인다. 도메인 3개부터 TAG inter-task affinity를 감시 지표로 추가.

**통과 게이트** ① TabM/twohot 헤드가 Stage 2 분위수 헤드를 페어드로 ≥0.03 이긴다. ② Deep Sets 풀링이 Hawkes 고정 커널을 페어드로 이긴다 — 못 이기면 고정 커널을 유지한다(파라미터 0이 이기면 그게 정답이다). ③ 3번째 도메인 추가가 기존 두 도메인 성적을 −0.03 이상 훼손하지 않는다(부정 전이 게이트). ④ 80% 구간 반폭이 0.45 log10(≈8배 밴드) 아래로 내려가면서 4셀 조건부 커버리지 유지. ⑤ 캘리브 표본이 n_cal≥300이 되어 커버리지 해상도가 2.3pp로 개선된다.

### Stage 4 — 프론티어 재판정 (총 n≥5,000, IP당 반복 관측 두터움)
**할 일** 여기서야 리서치의 프론티어 목록이 재판정 대상에 오른다: CARTE(스키마 불일치 다도메인 공동학습 — 단 한국어 엔티티 커버리지를 자체 폴드에서 페어드로 먼저 검증), TabPFN 텍스트 어댑터(PCA 병목 제거), mTAND(이력 10건 이상 IP가 다수일 때), 학습형 공유 인코더 종단간, LoRA/Houlsby 어댑터(도메인 5개 이상), 스택 앙상블(중첩 CV로 GBDT·TabPFN·GP·LLM을 비음수 릿지 결합). 또한 popga GA4 47M 이벤트를 비라벨 코퍼스로 재정의해 JEPA류 자기지도 사전학습의 전제가 성립하는지 재검토.

**통과 게이트** ① 각 프론티어 기법이 Stage 3 스택을 같은 폴드에서 페어드로 이긴다 — 벤치마크 논문의 주장이 아니라 우리 데이터의 실측으로. ② CARTE는 한국어 엔티티('더현대 성수', '쏘스뮤직') 커버리지 절제를 먼저 통과해야 한다. ③ 어떤 기법도 유지보수 부담 대비 이득이 0.03 log10 미만이면 채택하지 않는다. ④ 이 단계에서도 상시 병주하는 모델-프리 하한과 GBDT 레인을 제거하지 않는다 — 프론티어가 하한을 못 이기는 순간이 오면 그게 신호다. ※ 이 목록의 Neural ODE/CDE·THP·RoPE·전체 TFT·Perceiver/MBT·크로스 어텐션·TabNet·NODE·SAINT·하이퍼볼릭 임베딩·metapath2vec·DHE·메타학습 콜드스타트는 시퀀스 길이·표본 규모 조건이 우리와 자릿수로 어긋나므로 Stage 4에서도 착수 대상이 아니다.

## 부록 — 리서치 트랙 (fit_for_us=high)
- **Late fusion (2단계: 텍스트 인코더 동결 → 저차원 임베딩 → GBDT/선형)** — 텍스트를 학습 가능한 브랜치로 두지 않고, 동결된 사전학습 인코더로 벡터화한 뒤 8~16차원으로 줄여 정형 피처와 단순 concat → GBDT(또는 릿지)에 투입. 학습 파라미터가 텍스트 쪽에 0이므로 텍스트가 소수 샘플일 때 과적합 경로 자체가 봉쇄된다.
  - 언제 이김: n<2000, 텍스트가 보조 신호, 정형 피처가 주력일 때. AutoGluon 팀의 18개 tabular+text 벤치마크에서 이 2단계 파이프라인이 종단 신경망 융합을 일관되게 이기거나 대등했고, 우리처럼 정형 15 + 텍스트 24차원인 구성에 정확히 해당한다.
  - 비용: CPU 수 분. 코드 30줄 미만. 임베딩 캐시하면 재학습 1초.
- **TabPFN v2 (사전학습 표 기반 파운데이션 모델)** — 합성 표 데이터 사전분포로 미리 학습된 트랜스포머가 in-context learning으로 예측 — 우리 372건을 '컨텍스트'로 넣기만 하면 학습이 끝난다. 파라미터를 우리 데이터에 맞추지 않으므로 소표본 과적합이 구조적으로 불가능하다.
  - 언제 이김: n≤10k, 피처 수 적음. v2는 회귀·범주형·결측·텍스트 컬럼을 네이티브 지원하고 **예측 분포(quantile)** 를 직접 내놓아 80% 구간이 공짜로 나온다. n<1000 구간은 설계된 스윗스팟이며 튜닝된 GBDT를 이긴다고 보고됨.
  - 비용: CPU 추론 초 단위(n=372면 무통), 소형 GPU면 즉시. 하이퍼파라미터 튜닝 0.
- **Modality dropout / ModDrop** — 학습 중 텍스트 블록 전체 또는 정형 블록 전체를 확률 p로 0 마스킹(마스킹 여부를 나타내는 indicator 비트를 함께 입력). 모델이 어느 한 모달리티에 과의존해 암기하는 경로를 끊고, 동시에 추론 시 결측 모달리티를 네이티브로 처리하게 만든다.
  - 언제 이김: 모달리티마다 과적합 속도가 다를 때, 그리고 결측이 많을 때. 우리는 둘 다 해당 — 텍스트 24차원이 헤드 입력의 62%를 차지해 가장 빨리 암기되고, 기획서 텍스트·면적·매장수에 결측이 다수다. SMIL은 90% 샘플이 모달리티 결손이어도 학습 가능함을 보였다.
  - 비용: 코드 3줄. 학습 비용 증가 0. p는 CV로 0.1~0.5 탐색.
- **Conformalized Quantile Regression (CQR) + Mondrian(그룹조건부) 보정** — pinball loss로 10%/90% 분위수를 회귀한 뒤, 홀드아웃 보정셋에서 conformity score의 경험 분위수만큼 구간을 늘리거나 줄인다. 분포 가정 없이 **유한표본 커버리지 보장**. 도메인별·라벨신뢰등급별로 보정 분위수를 따로 잡으면(Mondrian) 그룹 조건부 커버리지가 확보된다.
  - 언제 이김: '80% 예측구간을 캘리브레이션 평가한다'는 요구가 있을 때는 사실상 유일한 정답. 소표본에서 특히 강한데, 보장이 점근이 아니라 유한표본이기 때문. 80% 구간이면 보정셋 ~100건으로 충분하다(1/(1-α) 규칙).
  - 비용: 무시할 수준. sklearn GradientBoostingRegressor(loss='quantile') 2개 + numpy 분위수 한 줄. 어떤 점추정 모델 위에도 사후 부착 가능.

- **Hierarchical / mixed-effects partial pooling (random intercept per domain & per IP; LMMNN)** — 도메인·IP·기획사·장소를 고정효과가 아니라 랜덤효과로 두고, 관측 수에 따라 전체 평균 쪽으로 자동 수축시킨다. LMMNN은 이를 Gaussian NLL 손실로 DNN 안에 넣어 SGD로 학습하는 형태(고카디널리티 범주 + 반복측정에 특화). 현재 preprocess.py의 shrink(n/(n+3))는 이 아이디어의 수제 근사 — 수축 강도 k를 손으로
  - 언제 이김: IP의 82%가 1회 관측 같은 극단적 롱테일 범주, 도메인 간 절편 차이가 큰 경우. 소표본에서 one-hot/임베딩보다 일관되게 강함.
  - 비용: 낮음. torch에서 (μ, log σ_re) 파라미터 추가 + NLL. 또는 statsmodels MixedLM로 선형판 먼저.
- **Uncertainty weighting (Kendall) — 태스크 가중 + 라벨신뢰 이분 활용** — 동분산(homoscedastic) 태스크 불확실성 σ_t로 손실을 자동 가중: L = Σ (1/2σ_t²)L_t + log σ_t. 우리에겐 두 갈래로 쓸모가 갈린다 — (a) 태스크 가중은 도메인 2개면 자유 스칼라 1개라 그리드 서치가 더 빠르고 안전하다(low). (b) **이분산(aleatoric) 헤드**는 고가치: 헤드가 (μ, log σ)를 내
  - 언제 이김: 라벨 잡음이 관측마다 다를 때(우리의 A~E 등급이 정확히 이것), 그리고 점추정과 구간을 한 모델에서 낼 때.
  - 비용: 헤드 출력 1→2, 손실 교체. 20줄 미만.
- **FiLM 조건화 + 도메인별 정규화 (DSBN / per-domain LayerNorm affine)** — 공유 잠재 z에 도메인별 아핀 변조 z' = γ_d ⊙ z + β_d 를 건다. DSBN이 BN 통계만 도메인별로 분리하고 나머지를 전부 공유하는 것과 같은 원리 — 도메인 고유 분포는 정규화 파라미터에 흡수시키고 표현은 공유. 도메인 원-핫을 concat하는 방식보다 엄밀히 강하다(원-핫 concat은 절편만 바꾸지만 FiLM은 스케일까지 바꾼다).
  - 언제 이김: 도메인별 출력 분포·피처 스케일이 다른데 표본이 부족해 별도 인코더를 못 둘 때. 정확히 우리 상황.
  - 비용: 도메인당 2×LATENT = 16 파라미터. 사실상 공짜. 어댑터의 최소 사례이자 우리 규모에 맞는 유일한 버전.
- **도메인별 타깃 정규화 + 분위수 정합 (per-domain target normalization)** — log10 → 도메인별 z-정규화(현 preprocess.TargetScaler, P6)까지는 이미 되어 있다. 한 걸음 더: 도메인별 **분위수 변환**으로 공통 정규분포에 사상해 공유 손실을 계산하고, 보고·채점 시에만 도메인별로 역변환한다. 초동(수천~수십만, 극단 우편향)과 팝업 방문(수천~수십만이지만 분포 모양이 다름)의 꼬리 모양 차이가 공유 트
  - 언제 이김: 두 타깃의 로그 분포 모양(왜도·첨도)이 다를 때. 아이돌 초동은 팝업보다 훨씬 두꺼운 우측 꼬리를 가질 가능성이 높다.
  - 비용: sklearn QuantileTransformer(output_distribution='normal') 한 줄. 단 소표본에서 분위수 추정이 불안정하니 train fold 내에서만 fit하고 n<200 도메인은 z-정규화 유지.
- **Conformalized Quantile Regression + Mondrian(도메인별·신뢰등급별) 캘리브레이션** — 분위수 회귀로 [q10, q90]을 내고, 홀드아웃 캘리브레이션 셋에서 conformity score로 구간을 조정해 **유한표본 커버리지 보장**을 얻는다(분포 가정 없음). 우리의 80% 구간 요구에 정확히 대응. 결정적으로, 도메인마다 출력 분포가 다르므로 캘리브레이션은 **도메인별로 분리(Mondrian/group-conditional)** 해야 한
  - 언제 이김: 점추정 모델이 무엇이든(LLM 포함) 감싸서 구간을 만들 수 있고, 이분산에 적응해 균일폭 conformal보다 짧은 구간을 낸다. 현재 커버리지 100%(n=9) 같은 과소확신을 통계적으로 교정.
  - 비용: MAPIE(sklearn-contrib, sklearn 1.6 호환) 또는 자체 구현 50줄. 그룹당 캘리브레이션 표본 50~100 필요 — 팝업 372에서는 여유, 아이돌 250에서는 빠듯. 교환가능성이 깨지는 시간 드리프트에는 Barber et al.의 가중 분위수
- **Deep ensembles (시드 앙상블 5~10개)** — 동일 구조를 다른 시드로 여러 개 학습해 평균(점추정)과 분산(에피스테믹)을 취한다. 근사 베이지안 NN·MC dropout과 대등하거나 그 이상이면서 하이퍼파라미터 튜닝이 거의 없고 병렬화가 자유롭다. 우리 모델은 파라미터 수백 개라 10개 앙상블도 CPU에서 수 초.
  - 언제 이김: n이 작아 시드 분산이 일반화 오차의 큰 부분을 차지할 때 — 현재 NN MAE 0.53의 상당 부분이 여기서 올 가능성이 높다. 콜드스타트 IP(관측 0~1건)에서 앙상블 분산이 자동으로 커져 구간을 넓힌다.
  - 비용: 학습 루프를 시드로 감싸는 것뿐. 사실상 공짜. 반드시 먼저 할 것.
- **GBDT 대조군 (HistGradientBoosting / CatBoost) + 도메인 증강 피처** — NN 아키텍처 논쟁 이전에 반드시 세워야 하는 통제선. 45개 데이터셋·2만 시간 하이퍼서치 벤치마크에서 트리 계열은 ~1만 표본 규모까지 여전히 SOTA이며, 그 이유가 (a)무정보 피처에 강건 (b)데이터 방향성 보존 (c)불규칙 함수 학습 용이 — 우리 피처 구성(결측 다수·범주 다수·비정형 스케일)이 정확히 트리에 유리한 조건이다. 도메인 전이는 D
  - 언제 이김: 항상 — 최소한 하한선으로. 도메인별 GBDT / 풀링 GBDT / 증강 GBDT 3종을 같은 폴드로 돌리면 '전이가 이득인가'라는 질문 자체에 NN 없이 답이 나온다.
  - 비용: sklearn 1.6에 내장. 결측 네이티브 처리. 수 초. 단 예측구간은 별도(분위수 손실 3개 모델 또는 conformal).
- **LLM을 사전정보로 흡수 — residual stacking (TabLLM 계열)** — 현재 LLM이 이기고 있다면 이기는 쪽을 피처로 삼는 것이 최단 경로다. harness/predictor_llm.py의 stage1 출력(총 소비자 성과 추정)과 그 근거 태그를 입력 피처로 넣고, NN/GBDT는 **잔차**와 **구간**만 학습한다. TabLLM은 테이블 행을 텍스트로 직렬화한 LLM이 극소표본에서 부스팅 트리와 대등하거나 우위임을 보였
  - 언제 이김: 소표본이고 도메인 지식이 학습 데이터 밖에 있을 때. 도메인이 늘어도 LLM 피처는 그대로 이식된다(어댑터 계약 7종 중 프롬프트만 갈아끼움).
  - 비용: 이미 있는 LLM 예측기를 폴드마다 호출(프리픽스 캐시로 완화됨). 주의: 백테스트에서 LLM 피처는 반드시 각 폴드 컷오프 이전 정보만으로 생성해야 하고, 그 자체가 누출 검증 대상.
- **라벨 신뢰등급 A~E의 가중 학습 — 고정 배수에서 잡음분산 모델링으로** — 현재 TRUST_W={A:1.0,B:0.8,C:0.5,D:0.25,E:0.25}를 MSE에 곱한다. 통계적 정본은 가중 = 1/σ²이므로, 등급이 σ의 **하한**을 정하고 나머지는 학습되게 하는 이분산 NLL이 맞다(D등급이 실제로 정확하면 모델이 σ를 낮출 수 있어야 한다). 부수효과가 중요하다: 등급별 σ가 곧 구간 폭에 반영돼 저신뢰 라벨이 구간을 
  - 언제 이김: 라벨 출처가 이질적일 때. 아이돌 도메인은 한터 전사(B)·써클 API(B)·나무위키(C)가 섞여 이 문제가 더 심해진다.
  - 비용: 손실 함수 교체 + 등급별 σ 하한 5개 파라미터. 낮음.
- **임베딩 저차원 사영 — PCA / Matryoshka 절단 / 랜덤 사영** — 1024차원을 8~32차원으로 떨어뜨려 넣는다. 세 경로: (a) 폴드 내 train에만 fit한 PCA, (b) Matryoshka(MRL, arXiv 2205.13147) 지원 모델에서 앞 32/64차원을 그냥 자르기 — 최대 14배 축소에도 정확도 유지가 원 논문 주장, (c) Johnson-Lindenstrauss 랜덤 사영(sklearn.rando
  - 언제 이김: 표본이 차원보다 작을 때 언제나. 특히 MRL 절단은 폴드마다 재적합이 필요 없어 rolling-origin 백테스트에서 '폴드 간 피처 정의 불변'이 공짜로 보장된다 — PCA는 폴드마다 회전이 바뀌어 봉인 장부와 궁합이 나쁘다.
  - 비용: MRL 절단은 0. PCA는 sklearn 한 줄, 폴드당 밀리초.
- **LLM 속성 태깅 (고정 온톨로지 구조화 추출)** — 임베딩 대신, 기획서를 LLM에게 읽히고 미리 고정한 스키마의 이산 속성 30~60개로 뽑는다(체험요소 유형, 굿즈 유무, 예약제 여부, IP 인지도 티어, 포토존 수, 콜라보 강도…). arXiv 2604.11835(Schema-Adaptive Tabular Representation)가 구조화 변수를 의미 문장으로 바꿔 인코딩하는 계열이고, 2509.2
  - 언제 이김: 소표본에서 항상 임베딩보다 낫다 — 60개 이산 피처는 n=372에서 학습 가능하지만 1024차원 실수벡터는 아니다. 게다가 결측·신뢰등급 태깅과 같은 문법이라 기존 라벨 온톨로지 규율에 그대로 얹힌다.
  - 비용: 레코드당 LLM 1콜. 에이전트 2패스 프로토콜(core/agent_task.py)로 돌리면 API 비용 0원. 온톨로지 설계에 사람 하루.
- **LLM 예측치를 피처로 쓰는 스태킹 / 잔차 학습** — LLM 예측기를 이기려 하지 말고 입력으로 삼는다. 소형 모델의 피처 = [LLM 점추정 log10, LLM 구간폭, LLM 2단분해 중간값(stage1 총성과), 수치·범주 피처, 축소 임베딩]. 학습 타깃은 실측 또는 실측−LLM추정(잔차). 형식상 LLM-as-teacher의 가장 값싼 형태다.
  - 언제 이김: 교사가 학생보다 압도적으로 강할 때 — 정확히 지금 상황(0.07 vs 0.53)이다. 소형 모델은 '예측'이 아니라 'LLM이 어디서 틀리는지'만 배우면 되고, 이건 잔차 구조가 단순해 소표본에서도 학습 가능하다. 도메인·신뢰등급·결측패턴별 계통 편향 보정이 전형적 수확 지점.
  - 비용: 구조 변경 최소. 이미 cycle_log에 (자극, 조건, LLM예측, 실측) 튜플이 쌓여 있으므로 학습셋이 이미 존재한다. 추론 시 LLM 1콜은 여전히 필요.
- **TabPFN v2를 소형 모델 백본으로** — 사전학습된 타불라 트랜스포머로 in-context 학습만 하고 파라미터 갱신이 없다. v1(arXiv 2207.01848)이 정확히 '학습 1000건 이하'를 겨냥해 설계됐고 부스팅 트리를 압도한다고 보고. v2는 회귀(TabPFNRegressor)·결측치·범주형을 네이티브 지원한다.
  - 언제 이김: n<1000, 이질 피처, 결측 다수 — 우리 조건의 교과서적 정의다. 직접 짠 NN이 0.53으로 지는 구간에서 TabPFN은 하이퍼파라미터 튜닝 없이 강한 하한선을 준다. 최소한 'NN이 진 게 데이터 탓인지 구현 탓인지'를 가르는 심판으로 반드시 세워야 한다.
  - 비용: pip install tabpfn, Python 3.10+. CPU 추론은 느리다고 공식 문서가 경고하지만 372건 규모면 감내 가능. 도메인별 별도 인스턴스(공유 인코더 가설은 표현 못 함).
- **분할 컨포멀 / CQR + Mondrian(신뢰등급별) 구간** — 점추정기와 무관하게 80% 구간을 사후에 만든다. arXiv 2107.07511이 표준 레퍼런스 — 분포 가정 없이 비점근적 커버리지 보장. 여기에 더해 TabPFNRegressor는 predict(output_type='quantiles')로 기본 [0.1…0.9] 분위수를 직접 뱉으므로 0.1/0.9만 취하면 80% 구간이 공짜다.
  - 언제 이김: 캘리브레이션 평가를 하는 지금 요구사항에 정확히 대응. 점추정 모델을 무엇으로 바꾸든 구간 레이어는 그대로 재사용되므로, 모델 교체 실험의 비용을 낮춘다. 신뢰등급 A~E별로 그룹을 나눈 Mondrian 컨포멀이면 '라벨이 나쁜 건은 구간을 넓힌다'는 기존 gate 철학과 같은 결론을 데이터로 유도한다.

- **LLM 예측을 오프셋으로 두고 잔차만 학습 (+ LLM 구간 컨포멀 보정)** — LLM이 log10 MAE 0.07이고 NN이 0.53이면, NN을 개선할 게 아니라 LLM 위에 얹어야 한다. ŷ = ŷ_LLM + g(x, ŷ_LLM, 등급, 단위)로 두고 g는 소용량 모델(GBM, depth 3)로 잔차만 학습. LLM 구간은 컨포멀로 재보정해 80% 커버리지를 맞춘다.
  - 언제 이김: 강한 사전지식 소스가 이미 존재할 때 — 우리 상황 그 자체. 0.53→0.07을 아키텍처 개선으로 메우는 건 372건에서 비현실적이지만, 0.07에 잔차 몇 %를 깎는 건 현실적이다.
  - 비용: LLM 예측을 전 학습셋에 대해 1회 생성해야 함(비용·시간). harness/predictor_agent.py 경로로 종량제 회피 가능. 오염 위험은 caveats 참조.
- **NN 폐기 → NGBoost / 분위수 GBM / TabPFN v2** — n<1000·이질 피처·결측 다수는 트리 계열의 홈그라운드다(Grinsztajn et al.: ~10k 이하에서 트리가 여전히 SOTA). NGBoost는 분포 전체를 출력해 80% 구간을 바로 주고, LightGBM quantile은 α=0.1/0.9 두 개로 구간을, TabPFN v2는 n≲1000·결측 지원·CPU 가능으로 우리 규모에 정확히 설계됐다
  - 언제 이김: 표본이 수백~수천이고 피처가 이질적일 때. NN 0.53은 아키텍처 문제가 아니라 모델 클래스 선택 문제일 가능성이 높다 — 먼저 이 베이스라인을 세우고 NN이 이기는지 확인.
  - 비용: 수 분. sklearn HistGradientBoosting은 결측 네이티브 처리. TabPFN v2는 CPU에서 ≲1000샘플만 실용적이라고 공식 문서가 명시 — 우리 규모에 딱 맞음.
- **다중 타깃 보조 헤드 (같은 이벤트의 상관 라벨)** — 요청의 'multi-label'을 도메인 간이 아니라 도메인 내로 적용. 팝업은 visitors·sales_krw·rev_mm이 곱셈적으로 연결돼 있고 아이돌은 초동·차트인·D+7 조회가 연결돼 있다. 이들을 보조 헤드로 함께 예측하면 레코드당 감독신호가 2~3배가 된다.
  - 언제 이김: 표본 수는 못 늘리지만 라벨 축은 늘릴 수 있을 때. 도메인 간 전이보다 훨씬 안전하다 — 같은 이벤트라 교환가능성·공변량이 동일.
  - 비용: 헤드 추가 + 결측 타깃 마스킹. 각 헤드의 손실 가중은 등급·단위 우도로 자연 결정(라벨 없으면 기여 0).
- **동결 다국어 텍스트 임베딩 + 차원축소 (또는 CARTE)** — 한국어 기획서를 372건으로 학습된 인코더에 태우는 건 불가능. 동결 multilingual 문장 임베딩(768d) → PCA/SVD 16~32차원 → 수치·범주와 concat. 더 나아가 CARTE(Kim et al. 2024)는 테이블을 그래프로 보고 문자열 엔트리를 임베딩해 '컬럼이 맞지 않는 여러 테이블의 공동 학습'을 지원 — 팝업·아이돌 스키마가
  - 언제 이김: 텍스트가 신호를 갖지만 표본이 인코더 학습에 턱없이 부족할 때. 차원축소를 안 하면 768차원이 372샘플을 압도한다 — 축소 차원은 CV로 정할 것.
  - 비용: 임베딩 1회 생성(CPU 수 분). CARTE는 사전학습 가중치 로드 필요, 중간 비용.
- **표 기반 파운데이션 모델(TabPFN v2 / Mitra / TabICL / TabDPT) — ICL 회귀 본체** — 합성 사전(prior)으로 사전학습된 트랜스포머가 학습 없이 in-context로 행을 조건화해 예측. 파라미터 갱신 없이 컨텍스트에 훈련행을 넣기만 함. TabPFN v2는 회귀에서 점추정이 아니라 전체 조건부 예측분포를 내놓음.
  - 언제 이김: n이 수십~1만, 피처 수 대비 표본이 적고 수치+범주가 섞인 이질 표. 토양 매핑 벤치마크 31개 데이터셋 n=30~460에서 TabPFN이 RF/PLS/FT-Transformer/TabR/TabM 전부를 제치고 종합 1위. 조건부 밀도추정 벤치마크(39개 데이터셋, n=50~20,000)에서도 CDE loss·log-lik·CRPS 대다수 1위.
  - 비용: 매우 낮음. n<1,000이면 로컬 CPU로 수 초. 학습 코드 없음. pip 설치 한 줄. (상업 이용 시 라이선스 확인 필요)
- **LLM을 예측기가 아니라 '피처 엔지니어·사전(prior) 생성기'로 강등 (FeatLLM / LLM Priors into Tabular Learners / FORESTLLM)** — LLM에게 숫자를 찍게 하지 말고 ①범주 수준의 순서 랭킹(기획사 티어, 장소 급) ②연속변수-타깃 상관의 부호·강도 사전 ③기획서 텍스트에서 이진/순서형 개념 피처 추출 규칙을 뽑게 하고, 하위 모델은 가볍게. FORESTLLM은 LLM을 학습 시점에만 쓰고 추론 시엔 경량 포레스트만 남김.
  - 언제 이김: 라벨이 수백 개뿐이고 도메인 지식은 풍부한데 그 지식이 표에 안 들어있을 때. 저데이터 구간에서 baseline 대비 일관된 우위, 해석가능성 유지. 우리 핵심 가설('팬덤 상태는 글로 표현되지 않는 잠재변수')을 LLM 순서형 스코어로 관측화하는 유일하게 표본효율적인 경로.
  - 비용: 낮음. LLM 호출은 피처 설계 시 1회성(도메인당 수십~수백 콜), 추론 시 0회. 이미 있는 predictor_llm.py 프롬프트 자산 재활용.
- **LLM 점추정을 피처/오프셋으로 넣는 스태킹·잔차 학습** — log10 LLM 예측을 하나의 컬럼(또는 오프셋)으로 TabPFN/GBDT에 투입하고 잔차만 학습. PROBE류 control-variate 관점에서 프록시-실측 상관을 온라인 추정해 가중.
  - 언제 이김: 강한 외부 예측기가 이미 있고 소표본 모델이 그것을 못 이길 때. 0.07 대 0.53 격차를 아키텍처 개편 없이 즉시 흡수. 단 LLM 우위가 진짜일 때만.
  - 비용: 매우 낮음. 컬럼 하나 추가. rolling 폴드마다 LLM 예측을 이미 뽑고 있으므로 추가 비용 없음.
- **컨포멀 예측 — CQR + jackknife+/CV+ (분할 없는 캘리브레이션)** — CQR은 분위수회귀 위에 컨포멀 보정을 얹어 이분산에 적응하는 구간을 만들고 분포무가정 커버리지를 보장. jackknife+/CV+는 별도 캘리브레이션 홀드아웃을 떼지 않고 LOO/폴드 예측만으로 유효 구간 생성.
  - 언제 이김: n이 수백이라 캘리브레이션 셋을 떼면 훈련도 캘리브도 둘 다 망가지는 상황. 정확히 우리 372건. 80% 명목 커버리지를 실증 커버리지로 맞추는 표준 도구.
  - 비용: 낮음. CV+는 K개 모델 재적합 필요하나 TabPFN은 학습이 없어 사실상 K번 추론. sklearn+numpy 100줄.
- **TabPFN 네이티브 조건부 밀도 → 80% 구간 + 사후 재보정** — TabPFN v2 회귀는 이산화된 전체 예측분포를 내므로 10%/90% 분위수를 바로 뽑을 수 있음. 여기에 컨포멀 재보정을 얹어 실증 커버리지를 명목에 고정.
  - 언제 이김: 소표본 CDE에서 파운데이션 모델이 CRPS·log-lik 최고. 다만 TALENT 112개 데이터셋 UQ 벤치마크에서 TFM은 점예측 최고 성능인데 조건부 커버리지(SSCS)는 GBDT보다 나쁨 — 그래서 '분포는 TFM, 커버리지는 컨포멀'의 2단 구성이 정답.
  - 비용: 매우 낮음. 이미 TabPFN을 쓴다면 추가 비용 0.
- **계층 베이즈 부분 풀링 (도메인·IP 랜덤효과) — '공유 인코더'의 소표본 정답형** — 전역 계수 + 도메인 수준 랜덤효과 + IP/브랜드 수준 랜덤효과. 공유 잠재상태를 자유 파라미터 신경망이 아니라 계층 사전으로 표현. 사후예측분포가 곧 캘리브된 구간.
  - 언제 이김: 도메인당 수백 건, 개체별 관측 1~10건인 콜드스타트. TSB-HB는 계층 사전의 부분 풀링이 희소·콜드스타트 아이템 추정을 안정화한다고 보고. 도메인이 늘어날수록(3, 4번째) 이득이 커지는 구조 — 우리 로드맵과 정확히 맞음.
  - 비용: 낮음~중간. numpyro/PyMC CPU로 수 분. 또는 statsmodels MixedLM으로 5줄 근사.
- **엔티티 이력 피처 (감쇠 집계형 'Career Trajectory Dynamics')** — IP/브랜드/기획사의 과거 개최·발매 이력을 last-value, 반감기 다른 지수가중 평균 2~3개, 직전 이후 경과일, 누적 횟수, 추세 기울기로 요약. 불규칙 간격을 신경망 대신 손으로 만든 감쇠 집계로 흡수.
  - 언제 이김: 인접 도메인에서 가장 큰 실증 효과. GAMENet(음악 인기 예측)은 CTD 피처 투입으로 R²가 0.13 → 0.69로 점프, 시간적 CTD가 추가 7%. 오디오·콘텐츠 피처보다 이력·모멘텀이 압도. Expo 참석 예측도 예약 동태 단독이 외부 다중소스보다 강함.
  - 비용: 매우 낮음. pandas groupby + ewm. 하루치 작업.
- **라벨 신뢰등급 A~E 이분산 가중 + Mondrian(그룹조건부) 컨포멀** — 등급별 관측노이즈 σ_g를 최대우도로 적합해 w_i ∝ 1/σ²_g 가중 최소제곱, 또는 GP/NN에 등급별 heteroscedastic likelihood. 동시에 등급을 컨포멀 그룹으로 써서 저등급 라벨에는 더 넓은 구간을 주고, 평가는 A/B 라벨에서만.
  - 언제 이김: 라벨 품질이 체계적으로 다를 때. 등급을 무시한 균등가중은 D/E 라벨의 노이즈를 신호로 학습해 소표본에서 특히 치명적. UPLME는 회귀 라벨노이즈에 heteroscedastic 불확실성 동시예측이 유효함을 보임.
  - 비용: 매우 낮음. sample_weight 인자 하나 + 컨포멀 그룹 키 하나.
- **순서형/구간 타깃 모델링 (Cumulative Binary Encoding / BinConv)** — 연속 log10을 로그 구간으로 이산화하되 one-hot이 아니라 누적이진 인코딩으로 순서 거리를 보존. 출력이 구간 CDF라 예측구간이 공짜로 나옴.
  - 언제 이김: 타깃 분포가 두껍고 라벨 정밀도 자체가 낮을 때. 아이돌 도메인은 이미 설계서상 로그 구간 라벨(한터 원숫자 재배포 금지 회피)이라 완벽히 정합. 게다가 LLM은 회귀보다 분류에서 훨씬 강하다는 실증(GPT-5/o3/Gemini 소표본 벤치마크)과도 맞음.
  - 비용: 낮음. 구간 K개짜리 분류 헤드 + CDF 후처리.
- **GBDT + pinball loss / NGBoost — 반드시 세워야 할 확률적 베이스라인** — LightGBM quantile objective로 10/50/90 분위수 3개 모델, 또는 NGBoost로 자연그래디언트 부스팅해 전체 모수분포 출력. 단조 제약(monotone_constraints)으로 도메인 사전 주입 가능.
  - 언제 이김: 결측 다수·고카디널리티 범주·분포이동이 있는 '오픈 환경'에서 TabPFN v2가 무너지는 구간을 GBDT가 방어. TALENT UQ 벤치마크에서 조건부 커버리지는 GBDT가 TFM보다 나음. 우리 NN 0.53이 상수예측 대비 개선인지 판정하는 기준선.
  - 비용: 매우 낮음. sklearn 1.6 / lightgbm.
- **파운데이션 모델 손익분기 규칙 (break-even decision framework)** — 30개 벤치마크에서 zero-shot/LoRA 파운데이션 모델 대 XGBoost/ARIMA를 훈련량 2%~100%로 비교. 실용 규칙: n_train < 700이면 파운데이션 모델 zero-shot을 쓰고 파인튜닝은 건너뛴다. 짧은 계열에선 LoRA 파인튜닝이 오히려 성능을 떨어뜨림.
  - 언제 이김: '우리 데이터로 파인튜닝하면 나아지지 않을까'를 결정할 때. 우리 n은 정확히 이 규칙의 왼쪽 — 파인튜닝 금지 구간.
  - 비용: 0. 의사결정 가드레일.
- **Split conformal (잔차 분위수) — 바닥 기준선** — 학습/캘리브 분할 후 |y−ŷ|의 ceil((n_cal+1)(1−α))/n_cal 분위수 Q 하나로 고정폭 구간 [ŷ−Q, ŷ+Q]. 모델 완전 무관, 재학습 0회, 유한표본 marginal 커버리지 보장.
  - 언제 이김: 점추정기가 이미 강할 때 압도적. 우리 LLM 예측기(log10 MAE 0.07)에 그대로 씌우면 80% 폭 ≈0.225 log10(1.7배)이 즉시 나온다. arXiv 2606.09473(2026)은 '학습 없는 컨포멀 구간'이 최신 확률 예측기들을 자주 이기며 반드시 병기해야 할 바닥선이라고 실증(2,217개 시계열).
  - 비용: 학습 1회, 추론 O(1), 코드 5줄. 대가는 데이터의 25~35%를 캘리브로 헌납하는 것 — 372건에서 n_cal≈74~130.
- **CV+ / jackknife+ / cross-conformal** — 캘리브 분할을 없애고 K개 폴드의 out-of-fold 잔차를 전부 캘리브 점수로 사용. 보장은 1−2α(실측은 거의 1−α)이며 알고리즘이 대칭적이기만 하면 분포 무관.
  - 언제 이김: n<1000에서 단일 split이 사치일 때. 우리 372건 기준 단일 split(n_cal=74)의 실현 커버리지는 Beta(60,15) → sd 4.5pp, 5~95% 범위 0.72~0.87, P(cov<0.75)=0.13. CV+는 372건 전부를 캘리브로 써서 sd를 ~2.1pp로 줄인다. 이것이 소표본 유효성의 핵심 레버.
  - 비용: K배 학습(K=5). 우리 MLP는 CPU 수 초라 무시 가능. state/encoder.py의 _split(n, folds=5)가 이미 같은 폴드를 만들고 있어 재사용만 하면 됨. jackknife+(LOO)는 n회 학습이라 372건까지는 가능하나 CV+로 충분.
