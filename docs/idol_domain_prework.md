## 1. 라벨 온톨로지 — "반응"의 단위 정의 (팝업 counting_method의 아이돌판)

팝업에서 라벨 단위 혼동이 100배 오차를 냈다. 아이돌 도메인의 단위 지도는 다음과 같다.
**모든 라벨에 단위 태그 필수. 서로 다른 단위끼리 앵커 금지.**

| 라벨 후보 | 단위 정의 | 출처 | 신뢰 기대 | 소급성 |
|---|---|---|---|---|
| **한터 초동** ★정본 | 발매 후 7일 실물 실판매(한터 패밀리 소매망) | 한터(재배포 금지)·한터뉴스 인증·나무위키 전사 | B (2차 전사 수% 오차) | 2세대~현재 |
| **써클 리테일 7일 합산** ★기계수집 정본 | 패널 소매점 POS 실판매 일간 합산, Top50 컷 | circlechart 내부 JSON API (무인증 실호출 검증됨) | B (패널<한터 커버리지) | 2019-04~ |
| 써클 주간 출하량 | 유통 납품(반품 포함 가능), 달력 주 절단 | 써클 앨범 API | C — 검증 보조용 | 숫자는 2022~ |
| MV 24h 조회수 | organic(공식) vs 카운터가 이원화, 기록급만 발표 | YouTube 발표·kworb | D — 라벨 부적격 | 사실상 불가 |
| MV D+7 누적 조회 | 공개 카운터, 자체 폴링 시 깨끗 | YouTube Data API | A (전향 수집분만) | 소급 불가 |
| 국내 차트인/최고순위 | 순위만(절대량 비공개) — 서열·이진 라벨 전용 | 멜론·써클 디지털 | C — 분포 극단 치우침 | 가능 |
| Spotify 차트 스트림 | 차트인 곡만 관측(비무작위 결측) | charts.spotify.com CSV | C — 보조 전용 | 2017~ |

**정본 라벨 = 초동, 3층 구조로 구축**:
① 나무위키 '역대 데뷔 음반 초동 기록' 전사(종단 골격) → ② 써클 리테일 일간 API 7일 합산으로
2019+ 교차검증 → ③ 대형 릴리즈는 한터뉴스 인증 기사로 보정. 층간 10%+ 불일치는 팝업과 동일한
교차검증 플래그 절차.

**저장·평가는 로그 구간 라벨** (예: <3천 / 3천~1만 / 1만~5만 / 5만~30만 / 30만+):
한터 원숫자 재배포 금지·써클 TDM 고지의 법적 리스크 회피 + Simile형 normalized accuracy 평가와 정합.

## 2. 사전 신호 (자극) — 시점고정 가능성이 채택 기준

시간 마스크가 **소급 보장되는 것만 1차 투입** (팝업의 누출 사고 예방 원칙):

| 신호 | 시점고정 | 비고 |
|---|---|---|
| 네이버 데이터랩 검색지수 | ◎ 소급 재구성 가능(2016~) | 공통 앵커 키워드로 정규화 필수. 저검색 신인은 0 뭉개짐 |
| 선주문량 보도 | ◎ 기사 날짜 | 좋은 숫자만 공개되는 선택 편향 → **'비공개' 자체를 음의 피처로** |
| 기획사 티어·데뷔 예고 | ◎ 증권사 리포트(하나증권 In-depth 등) | naive-3(업계 사전 예상)의 원천 |
| 위버스 커뮤니티 개설·쇼케이스 공지 | ◎ 공지 날짜 | 이진/시차 피처. 구독자 수는 비공개 |
| 서바이벌 출신 + 시청률 | ◎ 닐슨 익일 보도 | 데뷔 수개월 전 강신호 |
| 티저 조회수·SNS 팔로워 성장 | △ 전향 폴링만 | 과거 소급은 비무작위 결측 → **1차 백테스트 제외**, 전향 트랙 전용 |
| 팬 플랫폼 구독자(위버스·버블) | ✕ 비공개 | 막힘 |

## 3. 어댑터 계약 7종 매핑 (docs/ARCHITECTURE.md 계약 → 아이돌)

1. **레코드 스키마**: idol_debut_record {자극: 기획사·멤버구성·서바이벌·티저 롤아웃·선주문 보도,
   조건: 데뷔일·시장 환경(동주 경쟁 릴리즈)·유통, 결과: 초동(구간)·차트인·D+7 조회(전향분)}
2. **라벨 온톨로지**: §1 표 + 단위 태그 + 신뢰등급 A~E (그대로 이식)
3. **자극 빌더**: 데뷔일 이전 정보만 (§2 ◎ 항목), 실측 누출 차단 목록: 초동·차트·발매 후 기사
4. **다이제스트 빌더**: 뱅크 1줄 요약(기획사|데뷔일|유형|초동구간[신뢰]|신호태그) + 같은 기획사·같은
   유형 선례 전문 + 피처 태그(기획사 N번째 데뷔, 서바 출신, 검색지수 백분위)
5. **프롬프트+스키마**: 도메인 분해 = ①코어 팬덤 규모(선주문·검색·팬덤 신호) → ②초동 구간 변환.
   interval_paths를 merge_median에 바인딩(코어 재사용)
6. **naive 3종**: n1=기획사 티어별 중앙값 / n2=같은 기획사 직전 데뷔 / n3=증권사 전망·선주문 보도치
7. **게이트 재캘리브레이션**: 자극 빈곤 = 보도·공지 부재 신인 → 아이돌판 widen 배율은 첫 백테스트
   빈곤 폴드에서 역산 (팝업 4.5 이식 금지)

## 4. 첫 백테스트 뱅크 설계 (리서치 권고안 채택)

- **모집단**: 아이돌로지 연말 집계 기준 정식 데뷔 그룹 (연 35~43팀) — Fandom 카테고리(연 200+,
  솔로 포함)와 혼용 금지. 엔티티·데뷔일 수집은 Fandom MediaWiki API(무인증 검증됨) 후 그룹 필터.
- **기간**: 2019-04(써클 리테일 소급 시작) ~ 2026 상반기 ≈ 7년
- **예상 n ≈ 250~280** — 내부 팝업 뱅크(방문 80)의 3배, 학습 스택(신호→결과 환율) 첫 훈련장으로 충분
- **평가**: 구간 라벨 정확도(정확 구간/±1구간) + 서열 상관. 봉인·소모 장부·페어드 절제 프로토콜 그대로.

## 5. 크로스 도메인 연결 (상태모델 준비)

- 아이돌 엔티티 키를 팝업 뱅크의 brand_key·시장 층 ip_or_collab과 **같은 IP 그래프**로 정준화
  (통합 상태 인코더의 선결과제). 팝업 뱅크에 이미 있는 아이돌 IP: NCT 7건, 유노윤호, 뉴진스(시장) 등.
- 목표 구조: 공유 팬덤 상태(벡터) + 도메인 헤드(초동/팝업 방문). 전이 이득은 페어드 절제로 판정.
