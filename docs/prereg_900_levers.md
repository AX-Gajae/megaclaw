## 2. 팔

전부 `F18_bagboost`(챔피언) 의 하위 분류이고 **씨앗 0~11 로 짝짓는다**
(같은 씨앗끼리 뺀다). 팔마다 12적합.

| 팔 | 정의 | 게임 4열이 닿나 | 다른 11도메인에 생기는 것 |
|---|---|---|---|
| **A** (기준) | 오늘 챔피언 — `axis_order` 가 `AXIS_MODE="common"` | ✗ | 없음 |
| **B** | `axes = "union"` (`lab/forms.py:200-226`) | ✓ | 🔴 **0.5/마스크0 패딩 8열** |
| **C** | `DOMAX = {"게임": 4축}` (`lab/forms.py:837` · `_domax` `:976`) — 노트 529 가 **이미 만들어 둔** 장치 | ✓ | 🔴 **역시 0.5/마스크0 패딩 8열** (`_domax` 가 "모든 짝의 열을 만들고 자기 것이 아닌 자리는 중립(0.5)과 표시자 0" 이라고 명시한다) |
| **D** | B 와 같되, **그 도메인에 축이 아예 없는 칸을 0.5 가 아니라 NaN 으로** 채운다 | ✓ | NaN/마스크0 8열 (HistGradientBoosting 이 NaN 을 원생 처리한다 — `lab/forms.py:1136-1138` 이 명시) |

### 🔴 「도메인별로 자기 축만 보는 정식화」를 코드에서 먼저 찾았다 — 결과

지시가 요구한 확인이다. **찾았고, 그것도 패딩을 피하지 못한다.**

`BagBoost.DOMAX`(노트 529 · 기본 빈 사전이라 오늘 챔피언은 불변)가 바로
「그 도메인 행에서만 값이 있는 사본 열」이다. 그러나 `_domax`(`lab/forms.py:976-994`)
는 **모든 도메인에 대해 모든 짝의 열을 만들고** 남의 자리를 0.5/0 으로 채운다.
이유가 코드에 적혀 있다 — *"적합과 예보가 같은 자리를 써야 하므로"*.

즉 **이 아키텍처(단일 풀링 설계행렬)에서는 열 수가 도메인마다 다를 수 없고,
따라서 0.5 패딩을 피하는 정식화는 저장소에 없다.** 팔 D 는 그 패딩의 **값**을
바꿔 보는 팔이지 패딩을 없애는 팔이 아니다. **이 사실을 판정에 그대로 적는다.**

   둘이 같은 폭을 내는지도 확인한다.

3. **4축의 도메인별 실재**: 어느 도메인의 `names` 에 있나 · 유보 마스크 · 유보 고유값.
4. **자료 sha**(`lab.harness.fingerprint`) · **도메인 12** · **유보 가중 합 3,775** ·

6. 팔 B 와 팔 C 의 설계행렬이 **내용까지 같은지** 대조한다(4축이 정말 게임 전용이면

## 5. ④ 판정 — 어법을 미리 못 박는다

### 5.1 넘었을 때

Δ 하한 > 0 **이고** Δ > 0.00353 이면 → **「제안」까지만.**
**노트 133**: 첫 양수를 그대로 채택하지 않는다. 확인 측정은 다음 사이클.

### 5.2 못 넘었을 때 — 🔴 **"못 넘었다"가 아니라 "이 자를 못 넘었다"**

문턱 미달이면 세 가지를 **반드시 같이** 적는다:

1. **"이 자를 못 넘었다"** (판 문턱 0.00353 · 병기 0.00370)
2. **도메인 Δ 병기** — 12도메인 전부, 부호와 크기
3. 🔴 **"이 팔이 문턱을 넘으려면 도메인 Δ 가 얼마여야 하나"**
   — 899 가 그 수(아이돌 0.2611 · 시장팝업 0.1057)를 **갖고도 안 썼다.**
   이번엔 **코드가 계산해서 산출물에 적는다**(손 전사 금지):
   게임만으로 판 문턱을 넘으려면 `필요 게임 Δ = 문턱 × 3775 / w(게임)`.

### 5.3 🔴 게임만 좋아지고 남이 나빠지는가 (0.5 패딩의 대가)

미리 적는다:
- 게임 Δ > 0 **이고** 나머지 11도메인의 **가중 Δ 합 < 0** 이면
  → **「게임 전용 열이 남을 해친다」** 로 적는다. 899 의 「축이 있는 척한다」의 대가다.
- 게임 Δ ≤ 0 이면 → **「축을 닿게 해도 그 도메인조차 안 산다」**.
  그러면 남은 원인은 (가) 그 넷이 라벨과 무관 (나) 패딩 열이 그 넷의 값을 덮음 —
  **이 사이클은 둘을 못 가른다**고 적는다.

### 5.4 🔴 어떤 수가 나오면 「모른다」로 적을지 (미리)

| 조건 | 어떻게 적나 |
|---|---|
| 팔 X 의 `_design()` 열 수가 팔 A 와 **같다** | 그 팔은 **안 잰 것**. 「못 넘었다」로 안 적는다 |
| 짝 Δ 가 **정확히 0.0** (전 씨앗) | 887형 중립화 의심 → **「모른다」** + 배선 재검사 |
| 어떤 씨앗에서 채점 도메인 ≠ 12 또는 가중 합 ≠ 3,775 | 그 씨앗 **무효**. 12개를 못 채우면 그 팔은 **「모른다」** |
| BCa 실패/유실 > 10% → percentile 폴백 | 사유를 적고 판정은 **「자가 흔들렸다 — 유보」** |
| Δ < 문턱 **이고** 구간이 0 을 문다 | **「이 자로는 모른다」** — 반증이 아니다 |
| Δ < 0 이고 상한 < 0 | **「패」** (규약 47 `verdict`) — 이건 「모른다」가 아니다 |
| 팔 D 를 시간 안에 못 돌린다 | **「안 쟀다」**. 「못 넘었다」로 안 적는다(조항 59) |

### 5.5 안 하는 것 (미리)

- **정본 판을 갱신하지 않는다.** 이 사이클은 팔 비교다.
- **사후에 씨앗·도메인 부분집합을 고르지 않는다.** 12/12 전량으로만 판정한다.
- 탐색·지평 팔의 결과는 **이 사이클 결론에 안 들어간다**(`docs/루프.md` ⓪-다).
