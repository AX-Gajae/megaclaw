## §1. 원천 진단 (조항 66 — 실측 완료 · 사전등록 전 진단)

**기존 웹툰 개체의 원천 계보(코드로 확인):**

- 개체 = `WT-{네이버 웹툰 titleId}` (`ingest/webtoon_domain.py` — 네이버 웹툰 공개 API 명단).
- 곡선 = **한국어 위키백과 문서의 일별 조회수** — Wikimedia REST
  `metrics/pageviews/per-article/{lang}.wikipedia/all-access/all-agents/·/daily`
  (`ingest/wikidaily941.py` 규격 · 결측일 0 채움) → 상시 데몬이 성장시키는
  `data/ingest/wiki_daily959/웹툰.jsonl.gz` (개체별 «키·문서·날짜·조회수»).
- 언급(액션) = **HPLT 2.0 `kor_Hang` 웹문서**(`data/ingest/hplt_ko/train-*-of-00464.parquet` ·
  464 shard 전량 로컬 실물)가 그 개체의 위키 문서 제목을 언급한 것 —
  `runners/hplt973.py` 의 게이트 G1~G8(정제·중복 제거·언급 자)과 G9(창 덮기).
- 삼중쌍 = 언급일 D 에 대해 s = D−90…D−1 의 90일 조회수 · o = D…D+90 의 91일 조회수
  (`pretrain/triples.py` 가 (개체,언제) 중복 제거 · 개체 md5 해시 %10==0 → val).
- **지표 정의 문장**: 「값은 해당 개체의 위키 문서가 받은 일별 조회수(all-access ·
  all-agents · 원 눈금 정수)이고, 언급일 앞 90일이 상태 s, 당일부터 뒤 90일까지 91일이 결과 o 다.」

**사전 진단 실측(2026-08-19 · 이 문서 커밋 전):**

- 현 val 60행(9개체) 전부를 오늘의 곡선 스냅숏(`웹툰.jsonl.gz` sha256/16 `07b4aa36326259de`)
  에서 `hplt973.window()` 로 재계산 → **sao.npz 의 S·O 와 60/60 비트 일치** — 같은 원천이
  지금도 그 값을 낸다(원천 드리프트 0).
- 후보 풀: 곡선 보유 웹툰 개체 333 − sao 노출 60(=train 51 + val 9) = **미노출 273** ·
  그중 언급 자(`title_ok`·토큰≤5) 통과 **150**. bucket==0 만으로는 14 뿐이라 G2(≥21) 도달
  불가 — **해시 분할 규칙 밖 확충**이 필요하다(§3 명부 규약).

**확충 개체의 원천 = 위와 완전 동일**: 같은 곡선 파일(같은 스냅숏), 같은 HPLT shard 모집단,
`hplt973.py` 의 **생산 함수 임포트**(norm_title · toks_of · title_ok · strip_josa · mentions ·
window — 다시 만들지 않는다 · 조항 66) · `dupe954_hplt_scan.py` 의 도박 자·URL 정규화 호출.
**네트워크 수집 0** — 곡선·shard 전부 로컬 실물이므로 무료 API·UA·요율 조항은 발화 대상이 없다
(호출 0 을 §7 에 수로 게재).

## §3. 수집·선정 규칙 (결정론 · 인기 비의존 · 온보딩.md §1 미러)

1. **명단**: 곡선 스냅숏(주행 시작 시 `웹툰.jsonl.gz` 를 `/Users/ax/wm_harvest/1008/` 로 복사 ·
   sha 게재 — 데몬 성장으로부터 잰 소스 고정)의 웹툰 개체 중 sao(meta.jsonl)의 웹툰 개체 60 을
   뺀 **미노출 개체 전원**(≈273 · 언급 자 통과 ≈150). 전원이므로 화제성 컷 없음 · 상한 없음.
2. **스캔**: HPLT shard 를 **오름차순**으로, 973 이 이미 쓴 {0,58,116,174,232,290,348,406} 을
   빼고 훑는다. **예산 = 최대 128 shard.** 기계 중단 규칙: 각 shard 끝에서 「(개체,언제)
   중복 제거 후 유효 행 ≥1 인 신규 개체 수 ≥ 40」 이면 조기 종료(자 값과 무관한 «양» 규칙 —
   MdAPE 는 스캔 중 한 번도 계산하지 않는다). 128 shard 를 다 써도 21 미만이면 G2 실패로 적는다.
3. **게이트 자구 미러(973 = 같은 자)**: G1 filter=keep · G2 robotstxt=allowed ·
   G3 kor_Hang·prob≥0.9 · G4 도박 아님(S954.GAMBLE_PAT) · G5 길이≥200·한글비율≥0.5 ·
   G6 URL 정규화 첫등장 · G7 본문 첫등장(이 주행 범위) · G8 후보 개체 언급 ≥1 ·
   G9 창 덮기(정확 181일 연속) · 일반어 의심 표시(DF > 1% × 이 주행 G7 · 행 버리지 않고 표시 —
   973 자구) · 행 상한 300,000 미러.
4. **실패 3형(조항 59)**: 「없다」(그 개체 언급이 스캔 범위에 없다 — 수) · 「못 봤다」(언급 자
   미달 제목 123 = 273−150 · 미스캔 shard 수) · 「못 읽었다」(파싱·읽기 오류 — 사유를 값으로).
5. **(개체,언제) 중복 제거** — `pretrain/triples.py` 자구. 신규 행은 기존 val 행과 개체가
   겹치지 않으므로 기존 행과의 충돌은 원리상 0(0 임을 수로 게재).
6. **임베딩**: 배포와 같은 임베더 자구 미러(`runners/onboard1006.py phase_embed` —
   Qwen2.5-0.5B base 스냅숏 `060db649…` · 96토큰 · attention-mask 평균 풀링 · fp32 · CPU ·
   batch 16 · 유일 텍스트 중복 제거). 텍스트 조립은 `triples.py` 자구(문자열 필드 sorted ·
   「개체」「언제」 제외 · « · » join · 2000자 컷).
7. **산출물(저장소 밖)**: `/Users/ax/wm_harvest/foundation/triples/valext1008/` 에
   `val_ext_webtoon.npz`(S·O·year·doy·E·개체·언제) + `val_ext_meta.jsonl` + sha 명부.
   저장소엔 요약·경로·sha 만(>10MB 반입 금지).

**해시 분할 규칙과의 관계(명시).** 정본 분할은 «개체 md5 %10==0 → val»이다. 이번 확충 개체
150 중 bucket==0 은 14 뿐이므로, **명부 기반 val 전용 예외**를 만든다: ㉮ 신규 개체는 전원
sao 에 **한 행도 없던**(train 에도 val 에도 미노출) 개체라 개체 분리 원칙(누수 차단)은 그대로
성립한다 ㉯ 확충에 실제 편입된 개체 명단을 `data/lab/val_ext_roster.json` 으로 커밋하고
㉰ `pretrain/triples.py` 에 **유지 규약을 코드로** 넣는다: 재빌드 시 명부 개체는 분할을 val 로
강제한다(명부가 없으면 기존 동작 그대로 — 이번 사이클엔 triples.py 를 «실행하지 않는다» ·
sao.npz 불변). 데몬 상시 편입·망각 장부: 신규 개체 곡선은 이미 상시 데몬이 성장시키는
