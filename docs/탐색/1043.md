## §1 🔴 설계 전환 — 예측 경로에서 텍스트를 뺐다

문서 임베딩으로 유사 사례를 찾는 판은 **이미 실패했다**:

```
상위 20 유사사례의 실제 급등률  10%   vs  전체 기저 26%
→ 기저보다 «낮다». 쓸모없는 게 아니라 틀린 방향이었다.
원인: 동음이의어 — 웹툰 「인피니티」 질의에 «자동차 인피니티» 문서가 이웃으로 올라왔다.
```

그리고 1041 P2 가 오염을 걷어도 텍스트는 안 산다고 판정했다(텍스트를 더하면 −0.0343, 0 배제).

그래서 **역할을 나눴다**:

| 층 | 무엇으로 | 오염 |
|---|---|---|
| **검색 열쇠** | h64 궤적 상태 (1042 검증) | 없음 |
| **후속 사실** | 실제 91일 곡선 | 없음 — 진짜 일어난 일 |
| **서사** | 문서 + LLM | 있음 — 그러나 «설명»이지 «예측»이 아니다 |

이것이 이 대화에서 합의한 형태다 — **시뮬레이션이 아니라 인용**. 실제 궤적을 읽으므로
단계마다 오차가 곱해지지 않는다(1040 §3 의 「곱셈은 중간을 지운다」를 우회한다).
불확실성은 **「이 사례가 내 상황과 비슷한가」 한 번뿐**이고, 그건 곱해지지 않는다.

## §3 게이트 G1 판정 ✅

물음: *이웃들의 «실제» 급등률로 상위 10% 를 찍으면 기저율을 넘는가.*

```
풀: 창 12,567 · 개체 537 · 기저율 0.2963

  [관찰] K=10  P@10% 0.5056  (1.71배)  Δ +0.2006  SE 0.0138  CI95 [+0.1734,+0.2267]  ✅
🔴 정본 K=20  P@10% 0.5326  (1.80배)  Δ +0.2309  SE 0.0140  CI95 [+0.2041,+0.2575]  ✅
  [관찰] K=50  P@10% 0.5518  (1.86배)  Δ +0.2558  SE 0.0138  CI95 [+0.2280,+0.2818]  ✅
```

**세 K 전부 0 을 배제한다.** 정본 K=20 에서 상위 10% 로 찍은 것의 **53.3%가 실제로 3배 급등**했다
(기저 29.6% 의 1.80배).

🔴 **문서 임베딩 판과의 대비가 이 사이클의 요점이다**: 같은 물음에서 문서 검색은 기저보다
**낮았고**(10% vs 26%) 궤적 검색은 기저의 **1.80배**다. 열쇠를 바꾼 것이 전부였다.
⚠ 다만 두 판은 **표본이 다르다**(문서 판은 `(s,o)` 행 · 이 판은 패널 창) — **비율만 비교하고
AUC 를 잇지 않는다**(조항 60).


## §3-나 서사 층 — 만들었고, «오염 탐지기»로 작동한다

게이트를 넘었으므로 서사 층을 붙였다(`harness/story.py narrate`). 로컬 LLM(qwen3.6:35b-a3b)이
유사 사례의 문서를 읽고 「공통점 / 갈린 지점 / 조심할 것」으로 압축한다.

🔴 **문서 덮개가 낮다**: val 개체 582 중 본문이 있는 것 **108(18.6%)** · 개체당 중앙 4편.
그래서 수치는 유사사례를 100% 덮고 **서사는 덮는 만큼만** 내며, 그 비율을 출력에 적는다.

**실제 출력 (i=3521 · 덮개 8/20 = 40%)**

```
질의: 모바일|Just Dance (video game series) (2020-03-24)
[수치]  20건 중 17건(85%)이 3배 급등 — 기저 30% 의 2.87배
[서사]  공통점  — 'Stellaris' 급등 사례가 게임이 아니라 백내장 수술 장비·현미경으로 오인된 데이터 혼재
        갈린 지점 — 게임 시리즈와 의료기기가 같은 키워드로 묶여 실제 분석이 불가능
        조심할 것 — 🔴 문서가 'Just Dance'를 다루지 않으며 제시된 사례는 전부 무관한 타 개체 데이터
```

**LLM 이 그럴듯한 스토리를 지어내지 않고 「이 문서들은 이 개체 얘기가 아니다」라고 신고했다.**
프롬프트의 경고 조항(「문서가 그 개체를 실제로 다루지 않을 수 있다. 의심되면 그렇게 적어라」)이
작동했다.

**판정**: 서사 층은 **오염 탐지기로는 작동하고 스토리 생성기로는 작동 못 한다.**
문서↔개체 링크 오염(개체명 본문 0회 20.2% · 동음이의어)이 원인이고, 1041 P2 가 그 오염을
걷어도 «예측»엔 안 산다고 판정했지만 **«서사»에는 여전히 치명적**이다.
🔴 그럴듯한 거짓 서사를 내는 것보다 낫다 — 그러나 **지금 자료로 서사는 못 판다**.



## §3-다 오염 필터 — 서사 층을 열었다 ✅

§3-나 에서 서사가 「이 문서들은 이 개체 얘기가 아니다」로 끝났다. 그래서 **질의 시점 오염 필터**를
넣었다 — 전량 배치(30,428쌍 ≈ 14시간)가 아니라 **보여 줄 문서 18편만** 로컬 LLM 이 판별한다(30초).
🔴 판별 실패는 «뺀다»(조항 59 — 모르면 안 쓴다).

```
문서 18편 검사 → 통과 4 (22%) · 버림 14
버린 이유: Stellaris:«의료기기 이름» · The Sims 4:게임 콘텐츠 아님
          Hollow Knight:대상과 무관한 FF7 내용 · 주제가 아님
```

**동음이의어를 정확히 잡았다**(1036 §5 가 「언급 횟수로는 못 거른다」고 판정한 바로 그것).
그리고 통과분 4편으로 **실제 서사가 나왔다**:

> **공통점** 급등 사례는 「원피스」 콘텐츠 소비(다시보기·다운로드) 검색
> **갈린 지점** 급등은 구체 작품+시청 행위 / 비급등은 IP 이름만 있고 카페 소개 등 무관 내용
> **조심할 것** IP명이 있어도 콘텐츠 소비와 직접 연관이 없으면 급등이 안 난다

⚠ 통과율 22% 라 **서사 표본이 매우 얇다**(사례 3/20). 서사는 [관찰] 등급으로 읽어야 하고,
출력이 그 비율을 항상 함께 낸다.

## §4 안 주장하는 것

- **K=50 이 제일 좋다**(1.86배)는 [관찰]이다 — 정본은 K=20 으로 «미리» 고정했고 바꾸지 않는다.
