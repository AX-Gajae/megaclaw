# 1042 — P1 이 섰다: 궤적 파운데이션이 곡선 위에 증분을 준다

> 사전등록 커밋 `51d78f515` (측정 «전» 봉인) · 러너 `runners/panel1042.py`
> 자·라벨·기준선은 1039~1041 정본 승계 (조항 66).

## §1 왜 다시 물었나

1041 §5-1: P1 은 네 레인 전부 부호가 양수인데 CI 가 0 을 포함했다.
K=249 에서 MDE(2SE)≈0.037, 효과 +0.024 → **분모가 모자랐다.**
패널에 창 보유 개체 2,912 가 있는데 그때는 `(s,o)` 10,654 행만 쓰고 있었다.

## §2 🔴 누수 차단이 이 사이클의 핵심 설계

`pretrain/traj.py` 인코더는 **라벨은 안 봤지만 «궤적»은 봤다.** 그러므로
**인코더의 검증 개체(개체 분리 · seed 1041 · 582개)로만** 평가했다.
학습 개체로 재면 h 에 유리하게 기울고, 그건 1035 가 겪은 누수와 같은 형태다.

추가로:
- 창은 **STRIDE=91 로 겹치지 않게** — 겹치면 라벨이 서로 샌다
- 분할 10겹 **GroupKFold(개체)**
- 붓스트랩 **개체** 클러스터

## §3 판정 ✅

```
창 12,567 · 개체 537 · 기저율 0.296 · 겹침 없음

ⓐ37 곡선 (정본 기준선)     0.6943
ⓕ h64 (얼림 · 라벨 안 봄)   0.6631
ⓕ+ 곡선 + h64             0.7078

🔴 P1  Δ(곡선+h64 − 곡선) = +0.0135  SE 0.0026  CI95 [+0.0088,+0.0185]  ✅ 0 배제
[관찰] Δ(h64 단독 − 곡선) = −0.0313  SE 0.0061  CI95 [−0.0441,−0.0200]  ✅ 0 배제
```

**자기지도 표현이 손으로 짠 곡선 특징 위에 유의한 증분을 준다.**

읽는 법: **h64 단독은 곡선에 «진다».** h 가 곡선을 대체하는 게 아니라
**곡선이 못 담는 것을 보탠다.** 파운데이션 표현이 해야 할 일이 그것이다.

SE 가 1041 의 0.0184 → **0.0026** 으로 줄었다. 사전등록에 적어 둔 기대
(「K 만으로는 부족할 수 있고 클러스터 «안» 창 수가 커져 SE 가 줄기를 기대한다」)가 맞았다.
K 는 249→537 로 2.2배인데 창은 3,194→12,567 로 3.9배다.

## §4 🔴 잇지 말아야 할 것 (조항 60)

**1041 과 1042 의 AUC 를 나란히 놓지 마라.** 표본이 다르다:
- 1041: `(s,o)` 행 — 텍스트 매칭이 있는 개체만 · 기저율 0.257~0.273
- 1042: 패널 창 — 텍스트 조건 없음 · 기저율 **0.296** · 개체가 4배 넓다

1042 의 곡선 AUC 가 높은 것(0.6943 대 0.6307)은 «곡선이 좋아져서»가 아니라
**다른 표본**이기 때문이다. 비교 가능한 것은 **각 판 «안»의 Δ** 뿐이다.

## §5 안 주장하는 것

- **인과 아님.** 조건부 연관까지만.
- **+0.0135 는 작다.** AUC 0.6943 → 0.7078. 「파운데이션이 판을 바꿨다」가 아니라
  **「자를 넘는 증분을 준다」**이다.
- 표적은 여전히 «위키 91일 3배 급등» 하나다. **방문자·매출에는 안 꽂아 봤다**
  (1038 하네스는 n=104 라 훨씬 좁다).
- 인코더는 **HOR=30** 목적으로 학습됐는데 평가 라벨은 **91일**이다. 목적과 표적이 다르다 —
  그런데도 증분이 나온 것은 [관찰]로 유리한 쪽이지만, **맞춰서 재학습하면 어떻게 되는지는 안 봤다**.
