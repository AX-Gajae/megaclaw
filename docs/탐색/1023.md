## 3. 무엇이 바뀌었나 (수집기)

### ㉮ politeness 정정 — 전역 직렬 → 호스트별 (처리량 축 ①)
1017 의 `_sleep_gap()` 은 **전역** 1.1초라 서로 다른 호스트도 줄을 섰다. 규칙 원문은
「호스트별 ≥1.1초 · 서로 다른 호스트는 병렬 가능」 — 호스트별 잠금·시각으로 정정
(스레드 안전). **한 호스트에 대한 간격은 그대로 ≥1.1초다.**

### ㉯ --fullspeed 연속 모드 (처리량 축 ②)
```
   데몬 슬롯(시간당, 등기부)           전속 루프(nohup · --fullspeed)
   └─ 잠금 writer.pid 를 못 쥐면        └─ writer.pid 를 «쥔 채» 무한 회전:
      「무성장(잠금 접힘)」— 정상            사이클 = bing 전 명단 1,534 회전(주스레드)
      (1017 §3 규약 그대로 — 필자 1)              ∥ 보드 18 목록 300초 재폴링
                                                  ∥ 뉴스 43피드 600초 재폴링
                                             robots 사이클마다 재확인 · 스레드 ≤3
                                             load1>10 → 그 사이클은 bing 만
   본문 큐(nohup · 별도 프로세스)
   └─ 목록 gz 를 재스캔(180초) → 미수확 URL 을 호스트 분할 큐로 —
      워커 ≤6 · 매칭 행 우선 · bing 리다이렉트는 url= 파람 해소(bing 안 때림)
      필자 잠금은 별도(writer_body.pid — bodies/ 만 쓴다 · 목록 gz 필자는 1017뿐)
```

- 체크포인트 **공유**(코드로 확인): 전속 루프는 1017 의 `store()`·`seen_*.txt`·
  `bing_cursor.json`·`writer.pid` 를 그대로 쓴다 — 데몬 회차와 같은 gz 에 겹쳐 쓰는
  일이 원리상 없다(잠금이 접는다).
- 명단은 사이클마다 재적재 — 1016 원장이 자라면 쿼리도 자란다.

### ㉰ 본문 수집기 (처리량의 «깊이» 축)
