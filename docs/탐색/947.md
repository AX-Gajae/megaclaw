## 1. 안 한 것 — 사실 관계는 다시 안 쟀다

추적 `.npz` **10 전량**에서 `zipfile.namelist()`(`X.npy`)와 `numpy.load().files`(`X`)가
완전히 갈리고 `|zip−numpy| = |numpy−zip| = 전체 크기` 라는 것은 **티처와 주 세션이
이미 두 번 쟀다.** 다시 재면 그건 측정이 아니라 되풀이다.
남은 물음 하나만 봤다: **누가 두 판독기를 섞어 쓰는가.**

## 3. 🔴 같은 **함수** 안에서 두 이름이 만나는 자리 — **1** (절 나)

> `ingest/lifepop915.py:scan_zip`

두 자를 썼다(텍스트 정규식 → 파일 1, AST → 함수 1). **오늘 이 자리가 터지지 않는 이유는
`lab.keyspace.npz_names` 가 `.npy` 를 떼어 numpy 쪽 이름으로 맞춰 주기 때문이고
(`keyspace.py:187`), 그것은 「우연히 같은 쪽」이다.**

🔴 **그 정규화를 안 지나는 소비자가 numpy 쪽만 54 파일이다.** 둘이 만나는 날 그 54 가 분모다.
「안 걸렸다」이지 **「못 걸린다」가 아니다.**

## 4. NFC/NFD — 오늘의 0 은 **파일시스템 덕이다** (절 다)

- 추적 경로 **76,355** 중 **NFC ≠ NFD 인 것 260**
- **심은 키**: 그중 하나의 **NFD 판**을 추적 집합에서 찾아보니 **없다** →
  **이 파일시스템(APFS)이 NFC 를 돌려주므로 오늘의 0/0 은 참이다**
- 🔴 `unicodedata.normalize` 를 쓰는 `.py` **11** — 그런데 **그중 경로 이름 공간을
  지키는 것은 0**. 있는 것들은 전부 **본문 텍스트**용이다
  (`ingest/ko_titles.py` · `state/link_records.py` · `lab/ipjoin.py` …)

**다르게 정규화하는 파일시스템에서 clone 하면 그 260 자리에서 같은 병이 난다.**
