# 1044 — 🔴 판정 철회: G1 이 «자명 규칙»에 진다

> **2026-08-26 정정.** 아래 §3 의 「3.06배 · 원안이 축약을 이긴다」는 **허수였다.**
> 약한 기준선 둘(균등무작위·유형기저빈도)이 «시간 정보를 안 갖고 있어서» 이긴 것이고,
> 시간을 아는 한 줄짜리 규칙이 모형을 압도한다.
>
> ```
> 올바른 게이트 — «같은 개체의 미래 사건 중» 다음 것 고르기 (과제 526)
>   ㉠ 균등 무작위                 MRR 0.1882
>   ㉡ 유형 기저빈도               MRR 0.3569
>   🔴 ㉥ «가장 가까운 것» 자명 규칙  MRR 1.0000
>   모형 (인스턴스 벡터 138차원)     MRR 0.7855   ← 진다
>
> 무작위 후보(1044 가 쓴 자)에서도:
>   🔴 «같은 개체면 1» 한 줄 규칙    MRR 1.0000
>   모형                          MRR 0.8743   ← 진다
> ```
>
> **잘못이 세 겹이다.**
> ⑴ **과제가 동어반복이다** — 「다음 사건」은 정의상 「시간상 가장 가까운 미래 사건」이다.
>    시간만 보면 항상 100%다. 예측할 것이 없는 과제를 세웠다.
> ⑵ **기준선을 약하게 잡았다** — 🔴 1039 티처가 곡선 기준선에 대해 정확히 이 지적을 했는데
>    다섯 사이클 만에 반복했다. 약한 기준선은 「틀린 답」이 아니라 **「틀린 질문」**을 만든다.
>    물음이 「인과 구조를 배웠나」에서 **「개체·시간 정보를 갖고 있나」**로 바뀌어 버렸다.
> ⑶ **수치가 그럴듯해서 안 의심했다** — MRR 0.87·Hit@5 96%를 보고 「잘 됐다」고 적었다.
>    **높은 수치가 나오면 먼저 「자명한 규칙이 얼마를 내나」를 물었어야 한다.**
>
> **살아 있는 관찰 하나**: 후보를 «같은 개체의 다른 사건»으로 두면 MRR 0.8113 이다
> (「같은 개체」 단서가 원리상 안 통하는 설정). 다만 그 설정에서도 자명 규칙이 1.0000 이라
> **판정으로는 못 쓴다.** 시간이 안 통하는 과제를 새로 설계해야 한다 —
> 예: 「Δt 를 가린 채 다음 «유형»을 맞히기」 또는 「사건 후 관심 변화를 맞히기」.
>
> ⚠ **연쇄 영향**: 히스토리 트리(§4)가 1층 점수로 순위를 매기므로 **같이 흔들린다.**
> RoPE 인코더(§5)는 표적이 다르지만 **자명 기준선을 안 대봤다** — 별도 검사 필요.
>
> 아래 원문은 **역사 기록**으로 보존한다.

# 1044 — 사건 «인스턴스» 다층 행렬: 설계자 원안이 구현자 축약을 3배 이긴다

> 사전등록 커밋 `4eeb…`(1040)·`(1044 사전등록)` · 코드 `pretrain/eventmat.py`
> 자·누수차단은 1039~1043 정본 승계 (조항 66).

## §0 🔴 정정 — 1040 의 「유형 전이 행렬」은 원안이 아니었다

1040 이 「유형 전이 행렬 · |λ₂|=0.238 → k=3 사망」을 판정하고, 구현자가 그것을
**설계 실패로 기록**했다. **틀렸다.** 설계자 원안은 이랬다:

> 「event matrix 가 있고 이중 첫번째 layer 가 이벤트간의 인과성이고 나머지 레이어에
> 내부 상태 임베딩, 원문 임베딩, 수익, 시각 등의 정보가 있는거고, 시각에 따라서
> 인과성값을 보정해서, 인풋에 따라 벌어질 히스토리를 매트릭스의 첫번째 레이어에
> 프로젝션해서 계속 찾아내고, 이렇게 만들어진 히스토리 트리 여러 갈래중 상위 몇개를
> RoPE 인코더에 넣어서 뉴럴넷을 거친후 로스를 구해가면서 각 단계별로 어떤 숫자 변화가
> 생기는지를 파악」

노드는 **사건 인스턴스**이고 **각 노드가 벡터**다. 9개 «유형» 스칼라로 줄인 것은
**구현자의 축약**이었고, 이 사이클이 원안을 지어 둘을 직접 맞붙였다.

## §1 노드 — 다층 벡터

```
사건 인스턴스 8,416 (원장 19,507 중) · 개체 369 · 138차원
  유형        9      원핫
  RoPE(시각)  32     🔴 base=1000(일). 파장 6.3일~17년 — Δt 8~2,149일을 덮는다
                     (10000 이면 상한 172년으로 절반이 낭비)
  h64        64     1042 에서 결정층 증분 검증된 궤적 표현
  원문 PCA    32     덮개 76.9%
  결측 지시자  1      🔴 0 채움 금지 (조항 59)
버린 이유: 위키문서 없음 · 유형 밖 · 시각 없음 · 궤적 결측
```

## §2 1층 = 인과성 — 저장하지 않고 «계산한다»

```
A(i→j) = (W_q·v_i)·(W_k·v_j)/√d  +  f(log Δt)      🔴 시각 보정
조건:   t_j > t_i                                   역인과 금지
학습:   같은 개체의 «실제» 다음 사건이 정답 · 대조학습(InfoNCE) · 라벨 불필요

저장량: 8,416² = 7,083만 칸  →  138 × 8,416 = 116만 수
```

설계자 지적대로 **표가 아니라 함수**다. 관측 못 한 칸도 벡터에서 계산되므로 빈 칸이 없다.

## §3 판정 G1 ✅ — 원안이 축약을 3.06배 이긴다

후보 200개 중 «실제 다음 사건» 고르기 · 개체 분리 val 645쌍

| | MRR | Hit@5 |
|---|---|---|
| 기준선ⓐ 균등 무작위 | 0.0949 | 0.1256 |
| 기준선ⓑ **유형 기저빈도** ← 1040 유형행렬이 하던 것 | 0.2857 | 0.2961 |
| **모형 (인스턴스 벡터)** | **0.8743** | **0.9566** |

**MRR 0.2857 → 0.8743 = 3.06배.** 다음 사건이 **96% 확률로 상위 5개 안**에 든다.

🔴 **이것이 확정하는 것**: 1040 에서 행렬이 k=3 에 죽은 것은 **설계 탓이 아니라 축약 탓**이었다.
같은 자료·같은 사건인데, 9개 동의어 스칼라 대신 138차원 인스턴스 벡터를 쓰면 살아난다.

## §4 히스토리 트리 — 네 번 고쳤다 (전부 「기계는 도는데 뜻이 틀린」 종류)

```
v0    개체를 안 묶음        → 아무 데로나 뛴다 (안녕자두야 → 한돈자조금관리위원회)
v0.1  개체를 묶음          → 정당이 만화의 유사 사례
      🔴 h64 는 «도메인을 모른다» — 수준·도메인을 지우고 모양만 배웠다
v0.2  도메인 제약          → 갈래가 전부 한 개체(다양성 없음)
v0.3  개체마다 «따로» 사슬 → 전역 빔서치를 버렸다. 갈래가 개체 안에 잠기므로
                            빔이 한 개체에 먹힌다
```

**확정된 개념**: 갈래 = **«상태가 비슷했던 다른 개체»가 «실제로» 밟은 사건 사슬**.
시뮬레이션이 아니다(1040 §3 「곱셈은 중간을 지운다」와 1043 의 「인용」 논리 승계).

**실물 출력**
```
뿌리: [개봉] 안녕 자두야 (애니) · 유사 개체 풀 23
  [Steins;Gate 0]  유사도 -0.003 · 사슬점수 47.76   출시(+28일) → 출시(+56일)
  [히나마쓰리]      유사도 0.651 · 사슬점수 18.52   개최(+16일) → 개최(+400일)
  [베르세르크]      유사도 0.560 · 사슬점수 9.88    출시(+9일)  → 출시(+400일)
  [진격의 거인]     유사도 0.313 · 사슬점수 6.83    개봉(+64일) → 개봉(+114일)
```

🔴 **[관찰]**: 1위(Steins;Gate 0)의 h64 유사도가 **−0.003** 이다. 사슬점수가 압도해서
올라왔다. 순위 결합(`점수 + 4·유사도`)의 계수 4 는 **사전등록 없이 고른 값**이라
[관찰] 등급이고, 유사도 하한을 걸어야 할 수 있다. **다음 사이클 과제**.

## §5 RoPE 인코더 → 단계별 숫자 ✅

```
사슬(길이3) 7,796 · 개체 369 (val 73 · 개체 분리) · 파라미터 18,577
입력사영 → 🔴 RoPE 회전(상대 시각) → 멀티헤드 어텐션(4) → 헤드
표적: 각 단계에서 내재상태가 얼마나 움직였나 ‖Δh64‖ (z 정규화)

val L1 0.5021  vs  기준선(전부 평균) 0.9110  →  ✅ 44.9% 개선
```

🔴 **학습은 «실제» 개체 사슬로만 했다.** 트리가 만든 갈래로 학습하면 model exploitation —
트리가 모형이 가장 틀린 곳을 최선으로 고르고 헤드가 그걸 자신 있게 평가한다. 구조로 막았다.

## §6 안 주장하는 것

- **인과 아님.** 1층을 「인과성」이라 부르는 것은 설계 용어이고, 학습은 **예측**으로 했다.
  개입이 무작위 배정이 아니므로 조건부 연관까지만이다.
- **표적이 대리다.** §5 의 표적은 매출도 방문자도 아닌 **‖Δh64‖**(내재상태 이동 크기)다.
  기준 변수(방문자)로 바꾸려면 1043 §3-마 의 분모 문제(완비 43건)를 먼저 풀어야 한다.
- **순위 결합 계수 4** 는 사전등록 밖 [관찰].
- 원문 층은 **개체 단위 평균**이라 시점 정보가 없다. 사건별 원문이 아니다.
- **페르소나 결합은 미구현** — 팝가 GA4 가 BQ 읽기 전용에만 있다.

## §7 남은 것

1. 순위 결합 계수·유사도 하한을 **사전등록해서** 재기.
2. §5 표적을 **기준 변수(방문자)**로 교체 — 분모가 관문.
3. **페르소나 결합**(BQ 조회 필요).
4. 원문 층을 **사건 시점 기준**으로(지금은 개체 평균).
