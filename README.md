## MEGACLAW 가 무엇인가

**모형이 아니라 루프다.**

대부분의 연구 저장소는 *결과*를 담는다. MEGACLAW 는 **결과를 못 믿게 만드는 장치**를 담는다.
매 사이클마다 ① 예측을 측정 **전에** 봉인하고 ② 그 열이 정말 모형에 닿았는지 **비트로** 대조하고
③ 재고 ④ 판정한 뒤, ⑤ **이 사이클을 돌지 않은 프레시 세션**이 그 판정을 부순다.

이 구조가 실제로 무엇을 잡았는지가 이 저장소의 존재 이유다:

| 사이클 | 스스로 낸 결론 | 프레시 티처가 한 일 |
|---|---|---|
| 954 | 겹침 `D = 49.59%` → **보류** | **분자가 교집합이 아니었다** — 판정이 뒤집혔다 |
| 955 | 자를 바꿔 `19.556%` → **받는다** | 상수 `K=21` 이 **자료 자신에게 반증**됐다(같은 URL 이 478번 산다) |
| 956 | `17.025%` → **받는다 · 강함** | **「강함」을 자기 검사에 걸려 스스로 철회** |
| — | | 🔴 **세 사이클 모두, 판정이 무엇을 냈어도 집행은 같았다** |
| 957 | 「무관 배경」이 든다(`Δρ +0.0598`) → **배경이 아니라 도메인 이름표** | 🔴 **그 분해가 틀렸다** — 도메인마다 **모형을 다시 적합**했다. 모형을 고정하면 **안쪽이 `+0.0878`** 로 합산보다 크다 |

마지막 줄이 이 프레임워크의 요점이다. **자기 결론을 부수는 것을 파이프라인에 넣지 않으면, 무엇을 재도 자기기만이 된다.**

## 빠른 시작

```bash
git clone https://github.com/AX-Gajae/megaclaw.git && cd megaclaw
# 의존: python 3.9+ · numpy · pyarrow · (선택) scipy — 잠금 파일은 아직 없다

# ① 사이클 열기 — 오늘 할 일과 원천 상태를 낸다
python3 -m ingest.cycle_open

# ② 판을 재현한다 (판 ρ 정본)
python3 -m runners.rerun112                     # → runners/out112_board.json

# ③ 자료 원천을 수집한다 (등기부 `data/lab/sources.json` 이 정의한 것만)
python3 -m ingest.collect

# ④ 뒷걸음질 감시 — 원천별 행수가 줄면 붉어진다
python3 -m ingest.harvest_ratchet

# ⑤ 죽은 숫자 감사 — 아무도 안 쓰는데 문서에만 사는 수를 찾는다
python3 -m ingest.audit

# ⑥ 취합 검사 — 13개 절로 사이클 전체를 스스로 채점한다
python3 -m runners.fiveprime902
```

> **파이프 금지.** 긴 측정에 `| head` 를 붙이면 SIGPIPE 로 죽는데 **종료 코드가 0** 이다. 파일로 받아라.

## 코어 개념 넷

### 1. 자 (尺) — 문턱이 결론의 부호를 정한다

> 같은 자료·같은 팔인데 **자를 바꾸니 같은 결론이 36% 도 되고 146% 도 됐다**(노트 890~891).

```
판 ρ            0.47034 ± 0.0021   ← 0.0021 은 SD. SE 아님 (SE = 0.00060)
분모            12 도메인 · 유보 3,775 행 · 씨앗 0~11
채택 문턱 2σ    0.00353            ← 씨앗 0.00099 ⊕ 행 짝 0.00146, 널 팔 쌍으로 실측
재현            python3 -m runners.rerun112
```

🔴 **문턱은 분모에 딸린다.** 노트 957 이 쌍 39~464 짜리 층 실험에 이 문턱을 댔더니 **네 자리 전부
`2·SE_boot` 가 이겼다**(최대 **80.5배**). `0.00353` 은 「12도메인 · 유보 3,775」의 자이지 만능이 아니다.
**문턱을 인용할 때는 「어느 분모의 자인가」를 반드시 병기한다.**

### 2. 루프 — 프레임워크의 실행 단위

`docs/루프.md`(**v3.10**)가 정본이다. 한 사이클은 일곱 단계로 돈다.

```
⓪ 방향 설계     자를 뗄 것인가 · 원천 지평 · 탐색 팔
① 사이클 열기   ingest.cycle_open
② 프레시 연구   ← 누적 맥락이 없는 새 세션이 잰다
③ 논문          개선·반증이 있으면 LaTeX → paper.harness
④ 원장·PR       판정을 원장에 적고 note/<번호>-<슬러그> 로 PR (머지는 티처 뒤)
⑤ 프레시 티처   ← 이 사이클을 돌지 않은 자가 비평한다
⑤′ 취합 검사    13절 · 자기 산출물까지 채점한다
⑥ 인계 카드     다음 세션이 이것만 읽고 재개할 수 있게
```

**레인은 셋뿐이다** — `[판정]` · `[탐색]` · `[수리]`. 수리 레인은 한 사이클에 하나까지이고,
초과하려면 **사전등록 §8 에 「상한 N · 근거 · 어느 지시가 시켰나」를 측정 전에** 적어야 한다.

### 3. 사전등록 → 배선 검사 → 측정 → 판정

순서를 어기면 사이클이 무효다. 각 단계가 무엇을 막는지:

| 단계 | 산출물 | 막는 것 |
|---|---|---|
| **사전등록** | `docs/prereg_<노트>_<슬러그>.md` · **파일 하나만 담은 단독 커밋** | 첫 양수를 보고 문턱을 정하는 것(노트 133) |
| **배선 검사** | `out<노트>_*.json` 의 `W1..Wn` | 「측정했다」는데 그 열이 모형에 안 닿는 것 |
| **측정** | 입력 **sha256 을 산출물에 박는다** | 데몬이 측정 중 입력을 바꿔 재현이 깨지는 것(957 이 실제로 겪었다) |
| **판정** | `out<노트>_score.json` | 사후에 자를 고르는 것 |

🔴 **자유파라미터를 쓰면 「그 값이 바뀌면 판정이 어디서 바뀌는가」를 같이 적는다.**
955 가 `K=21` 로 여기서 걸렸다 — 판정이 **`K=503` 에서 뒤집혔고** 그 사실이 안 적혀 있었다.

### 4. 심은 키 (planted key) — 자가 정말 무는지 본다

「돈다」와 「막는다」는 둘이다. 새 검사기를 만들면 **일부러 병을 심어 붉어지는지** 확인한다.

```python
# 나쁜 심은 키 (955) — 통과 조건이 병 그 자체라 병을 재현하고 초록을 찍는다
assert norm(u) == norm(u + "?probe=1")        # ← 뭉치면 통과

# 좋은 심은 키 (956) — 실물 두 문서가 한 키로 뭉치면 붉어야 한다
a = "cdn.kado.net/news/articleView.html?idxno=1106516"   # 강원도 플랫폼 기사 (9,606 B)
b = "cdn.kado.net/news/articleView.html?idxno=1137305"   # 파월 연준 기사   (2,402 B)
assert norm(a) != norm(b), "서로 다른 기사가 한 키로 뭉쳤다"
```

- **층화 뒤섞기로 받는다** — 순서대로 받으면 중간에 끊길 때마다 표본이 편향된다.
  `runners/hplt_fetch.py` 의 비트 뒤집기 순열은 **어느 앞부분을 잘라도 고르다**
- 🔴 **받았다 ≠ 읽힌다** — `curl` 종료 코드 0 · stderr 없음 · 실물 135 MB 를 받고도
  **안 열리는 파일이 둘 나왔다.** 모든 수신은 `pyarrow` 로 실제로 열어 본 뒤에만 성공으로 센다

### 겹침을 재는 자 넷

두 코퍼스가 얼마나 겹치는지는 **자에 따라 3배가 달라진다.** 그래서 넷을 다 싣는다.

| 자 | 정의 | `D_문서` (÷ FineWeb 전량 60,874,355) |
|---|---|---|
| **① URL 정확** ← **정본** | 원 URL 해시 · **자유파라미터 0** | **17.025%** |
| ② URL 정규화 | 스킴·`www.`·쿼리 제거 | 상한 49.700% / 하한 없음 |
| ③ 본문 앞 200자 | md5 | 13.649% |
| ④ 전문 md5 | 전체 본문 | 6.693% |

🔴 **자② 는 뭉친다.** 하나의 정규화 URL 이 HPLT 문서 **79,766개**, FineWeb 문서 **248,343개**를 문다.
`?idxno=A` 와 `?idxno=B` 가 서로 다른 기사인데 같은 키가 되기 때문이다.
자① 도 완전히 깨끗하진 않다 — 분자의 **15.1%** 가 FineWeb 내부의 같은-URL 사본이다.

## 자기규율 조항

`docs/루프.md` 에 **62개**가 산다. 전부 **실제로 데인 자리**에서 나왔다.

> **59. 성공 신호는 작업의 성공이 아니다.**
> 종료 코드 0 · HTTP 200 껍데기 · 빈 응답 · 셸 확장.
> **제일 위험한 형태는 빈 것을 부정으로 읽는 것** — 「없다」와 「못 봤다」와 「못 읽었다」는 셋이다.

> **60. 한 표본으로 원천의 성질을 말하지 마라.**
> 두 수를 이어 붙일 때 **각 수의 분모가 같은지 확인하라.**
> — 이 실험실이 이 조항을 **이틀 연속 어겼다.** 코퍼스 앞 4 shard(= 한 크롤의 2주치)로 낸
> 「도박 3.869%」를 전량의 성질처럼 보고했다. 전량 참값은 **1.767%** 였다.

> **62. 「생산기가 찍었다」는 경로를 보증하지 분자를 보증하지 않는다.**
> 그리고 **산문은 아무도 안 본다** — 도장이 「키 이름 대 실제 계산 54/54」를 초록으로 찍는 동안
> 같은 노트의 산문이 「안 했다」고 거짓말했다. `runners/prose_check.py` 가 그것을 막는다.

## 재현성

```bash
python3 -m runners.rerun112              # 판 ρ 정본 재현
python3 -m runners.fiveprime902 --base <커밋>   # 사이클 전체 자가 채점 (13절)
python3 -m ingest.audit                  # 죽은 숫자 감사
python3 -m runners.prose_check           # 산문 주장 대 산출물 키 대조 (⚠ PR #215 가지)
```

- 모든 측정 산출물은 **입력 sha256** 을 함께 싣는다
- 문서는 **손으로 쓰지 않는다** — 생산기가 산출물 키에서 만들고 **도장(`out*_docstamp.json`)이 대조**한다
- 커밋은 **커밋된 트리** 기준으로 채점한다(작업 트리가 아니다 — `git HEAD` 스탬프는 긴 러너에서 「시작 시점」이라 폐기됐다)
